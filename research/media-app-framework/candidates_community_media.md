## Community findings (anecdotal)

1. Expo is treated as the default way to do React Native. A 2024 HN comment asks whether there is "any sane way" to use RN without Expo (HN 41937591). The counter-complaint is that Expo/EAS is "a paid tool with metered usage" (HN 46483023).
2. Upgrade churn is the most repeated RN complaint: the New Architecture migration, compiling again after time away, and per-year library bumps (HN 45225217, HN 43015267). The 2026 podcasts say AI tools now make upgrades "a little less of a headache" (RNR 357).
3. People doubt Google's commitment to Flutter. Examples: the 2024 layoffs, Flock's "maintenance mode" charge, and a 2026 comment asking why Flutter survived "the axe" (HN 49280061; DevClass). Defenders say "Flutter is fine" and "Flutter is doing great" (HN 46483023, HN 40746826). By 2026 governance is spreading to partners (Canonical runs desktop).
4. Flutter is praised for mobile UI quality and smoothness. Zulip rewrote its RN app in Flutter and calls it faster and smoother, and one commenter reports faster rendering. Flutter Web is widely criticized, and the nested widget syntax is a minor gripe.
5. The Shopify, Simon Willison, and Pragmatic Engineer thesis is that coding agents make two native codebases affordable again. Every native-with-agent report here (Simon Willison, Rodrigues, Skip) runs on a Mac with Xcode, which this project does not have.
6. Solo and indie developers who report shipping with Claude Code mostly chose Expo (Tippins, Wilson, HCB, Oh Yah, Peter without a Mac). Their common advice is to plan first in a written plan or CLAUDE.md, point the agent at the framework docs (Expo docs or MCP), and use a backend that agents handle well, such as Supabase or Firebase.
7. Views on Dart for AI agents are split. Some say it is underrepresented in training data. Others say its strong typing and hot reload help agents. A Flutter GDE says agents still fail on state management, platform channels, and performance (Alkamel), and Andrea Bizzotto reports a successful App Store ship with Claude Code.
8. Third-party native modules are a risk. Stale RN wrappers force you to write native code (Purohit). Any cross-platform layer still makes you learn the platform when a platform-specific bug appears (Skip thread). Apple and Google approval for advanced native features can take months (HCB).
9. A commenter warns about over-the-air updates (EAS Update): stay within Apple's rules or risk takedown (HN 46130260). This is anecdotal; check it against Apple's guidelines.
10. KMP, Swift-on-Android, and Skip get attention, but commenters cite thin libraries and Mac or Xcode dependence. None was recommended for a solo, no-Mac developer.
