## Learned points
1. [Documented] Current SDK rule, under the heading "Since April 28, 2026": apps uploaded to App Store Connect must be built with Xcode 26 or later, using an SDK for iOS 26, iPadOS 26, tvOS 26, visionOS 26 or watchOS 26. The previous step (since April 29, 2024) was Xcode 15 and the iOS 17 SDK. Before that (April 25, 2023) it was Xcode 14.1 and iOS 16.1. Apple raises the floor every spring, roughly one Xcode major per year.
2. [Documented] Minimum deployment target, under the heading "Since September 9, 2026": iOS and iPadOS apps uploaded to App Store Connect must target iOS 13 or later.
3. [Documented] Other current rules that affect a monetized app. Age ratings were updated to the new system, and you had to answer the updated questions by January 31, 2026 or app updates would be interrupted. EU DSA trader status is required (for updates since Oct 16, 2024; apps without it were removed in the EU from Feb 17, 2025). Approved-reason declarations are required for listed APIs, including in third-party SDKs (since 2024). On-device receipt validation must support SHA-256 (the SHA-1 intermediate expired January 24, 2025), or you use the AppTransaction and Transaction APIs. In-app purchase and subscription management moved from the XML feed to the App Store Connect REST API (the XML feed ended November 9, 2022).
4. [Documented] The page listed no future-dated requirement when I read it. Every entry reads "Since <date>". Neither this page nor the Xcode pages said when an Xcode 27 or iOS 27 SDK minimum will start.
5. [Documented] Xcode and macOS versions (system requirements table): Xcode 27, 27.1, 27.2 and 27.3 beta 2 need "macOS Tahoe 26.6 or later". Xcode 26.4.1–26.6 need macOS Tahoe 26.2–26.x. Xcode 26–26.3 need macOS Sequoia 15.6–Tahoe 26.x. Xcode 27.x includes the iOS 27.x SDK and deploys to iOS 15–27, with Swift 6.4.
6. [Documented] Xcode is a Mac app. The Xcode page describes simulators and the new "Device Hub" for physical devices and simulators as "Prototype on every device, all from your Mac". Nothing on the page describes Xcode running on another OS.
7. [Documented] Xcode 27 advertises "coding intelligence". It supports "the model of your choice, including the frontier coding models and agents from Anthropic, Google, and OpenAI". You can add "any agent compatible with the Agent Client Protocol" and extend Xcode "with your own skills and tools using the Model Context Protocol".
8. [Documented] Xcode Cloud is Apple's CI/CD service "built into Xcode". It builds, runs tests in parallel, analyzes and archives, distributes to TestFlight, and shows results in Xcode and in the App Store Connect web dashboard. Builds run in temporary environments that are destroyed when the build completes. Build artifacts are available for 30 days, so you should download and archive the ones you publish.
9. [Documented] Xcode Cloud requires Xcode 15.0 or later and Apple Developer Program membership. Setup is "configuring a workflow in Xcode". The workflow docs say: "Use Xcode to initially configure your project or workspace to use Xcode Cloud. After you complete your first build, use either Xcode or App Store Connect to configure additional workflows". App Store Connect on the web can then "edit your workflows and launch builds".
10. [Documented] Xcode Cloud pricing: 25 compute hours per month are included with program membership. Paid add-ons are 100 hours for US$49.99/month, 250 hours for US$99.99/month, 1,000 hours for US$399.99/month and 10,000 hours for US$3,999.99/month. Unused hours do not roll over. One compute hour is an hour of task time, for example "running 5 tests of 12 minutes each equals one compute hour". Only the Account Holder can subscribe, in the Apple Developer app.
11. [Documented] Xcode Cloud build environments run on macOS with Xcode, include Homebrew, and support custom build scripts. Each workflow sets its Xcode and macOS versions, and Apple "may periodically update available macOS and Xcode versions and ask you to update your workflows".
12. [Inferred] For a no-Mac developer, Xcode Cloud is not a clean fit. The very first workflow has to be configured in Xcode, so you need a Mac at least once (owned, borrowed or rented). It is also built around native Xcode projects, which suits Flutter (S6 shows a post-clone script) and bare or prebuilt RN, but not a Linux-only workflow. Third-party macOS cloud builders (for example, EAS Build or Codemagic; see their own sources) avoid that first-time Mac step.
13. [Inferred] The yearly SDK floor means any framework has to keep up with new Xcode releases. Cross-platform frameworks and cloud builders must update their macOS and Xcode images every year. A solo developer depends on that happening before Apple's April deadline.

## Limitations or bias
- These are Apple's own marketing and policy pages. They never discuss non-Mac workflows, so "needs a Mac" is shown by what the pages assume (Xcode on a Mac, setup in Xcode), not stated as a rule.
- The documentation pages are rendered with JavaScript. I read them through the JSON data endpoints, and my extraction dropped some link text and a command sample (the archive-scheme Terminal command).
- The Apple Developer Program fee is not on these pages, so it is not recorded here.
- The system-requirements table was extracted as flat text. I matched the Xcode-to-macOS pairs by position.
