## Learned points
1. [Documented] Projects created with `create-expo-app` include an `AGENTS.md` that points the agent to the docs for the project's SDK version. When Claude Code is installed, they also include `.claude/settings.json`, which enables the official Expo plugin. Both files are committed. "Reading AGENTS.md directly requires Claude Code v2.1.277 or later."
2. [Documented] Claude Code setup has three steps. Install Claude Code (`curl -fsSL https://claude.ai/install.sh | bash`). Run `claude plugin install expo@claude-plugins-official`, which "installs Expo Skills and registers the Expo MCP Server". Run `/mcp` inside the session to sign in to Expo. Add `--scope project` for a project-only install. The page's troubleshooting section covers the error "Plugin 'expo' is enabled in project settings but isn't installed here."
3. [Documented] The Expo MCP Server is remote: Streamable HTTP at `https://mcp.expo.dev/mcp` with OAuth. To add it manually: `claude mcp add --transport http expo https://mcp.expo.dev/mcp`. It requires an Expo account and a project on the latest SDK. It is also available as a Claude Connector (web, desktop, mobile) and for Cursor, VS Code, Codex, and Grok.
4. [Documented] Server-side MCP tools, which need no local dev server: `read_documentation` and `search_documentation` (search "requires an Expo Services paid plan"), `build_list/info/logs/run/cancel/submit` (`build_run` "Requires a GitHub repository to be connected to the project"), `workflow_*`, `testflight_crashes/feedback`, `appstore_reviews/reply_review`, `playstore_crashes/reviews/reply_review`, `observe_*` (production metrics, errors, traces), `sentry_issue`, `usage_budget_get/create`, `sandbox_*` (billable cloud sandboxes), and `simulator_start/get/list/stop`, which control cloud simulator sessions.
5. [Documented] On a cloud simulator session (`simulatorSessionId`), the MCP automation tools `automation_tap`, `automation_take_screenshot`, `automation_find_view`, `automation_type`, and `automation_scroll` work entirely through the server. `simulator_start` starts "a billed cloud simulator session", and idle sessions stop after a default of 10 minutes.
6. [Documented] Local capabilities need SDK 54 or later, `npx expo install expo-mcp --dev`, and `EXPO_UNSTABLE_MCP_SERVER=1 npx expo start`. They add screenshots, taps, and find-view on the local device, plus `open_devtools`, `collect_app_logs` (logcat/syslog/JS console), and `expo_router_sitemap`. Documented limits: a single dev server at a time; "iOS support for local capabilities is limited to simulators only"; "iOS support for local capabilities is only available on macOS hosts." You must reconnect MCP whenever the dev server restarts.
7. [Documented] Expo says it does not use MCP data to train AI models. For local capabilities, data such as screenshots is proxied through Expo's server to the client.
8. [Documented] The Expo plugin bundles these skills. Framework: `expo-animation`, `expo-app-clip`, `expo-brownfield`, `expo-data-fetching`, `expo-design-system`, `expo-dev-client`, `expo-dom`, `expo-examples` (about 70 `with-*` example integrations, such as Stripe, Supabase, OpenAI), `expo-module`, `expo-native-ui`, `expo-overview`, `expo-project-structure`, `expo-router`, `expo-ui` (SwiftUI and Jetpack Compose via `@expo/ui`), `expo-upgrade`, `expo-web-to-native`. Services: `eas-app-stores`, `eas-hosting`, `eas-observe`, `eas-simulator`, `eas-update`, `eas-update-insights`, `eas-workflows`. Agents other than Claude Code can install them with `npx skills add expo/skills`.
9. [Documented] The `eas-simulator` skill's description says it is the default on a host with no local simulator ("Linux, CI, cloud sandbox"). The trigger phrases it lists include "I'm on Linux/Cursor and need an iOS device" and "let an agent click through my app and screenshot it".
10. [Documented] Example Claude Code prompts in the docs: "Upgrade this project to the latest Expo SDK and fix any breaking changes", "My latest iOS build failed. Read the Expo Build logs and tell me what went wrong", "Show TestFlight feedback for my app", "Take a screenshot and verify the blue circle view."
11. [Documented] Structure of llms.txt: an intro, a "common misconceptions" block aimed at LLMs ("eject" removed in SDK 46, the managed/bare split is outdated, global `expo-cli` deprecated, "EAS" renamed to Expo Services, and claims that Expo apps perform as well as native), a Performance note (Hermes default; SDK 53+ fully supports the New Architecture), and then about 620 linked pages. Its sections include Get started, AI (agents, toolkits), Agentic workflows, Develop, Review, Deploy, Monitor, Expo Router, Expo Modules API, Push notifications, and Integrations (including "In-app purchases"). Any page is available as markdown via `.md` or `Accept: text/markdown`.
12. [Documented] On pricing (S2), the Expo MCP Server is "Fair use limited" on Free and included on paid plans. Doc search and cloud simulators require paid plans.
13. [Inferred] For Claude Code in a Linux container, Expo has the most complete agent toolchain of the options here. An official Claude Code plugin with skills and a remote MCP server lets the agent trigger and read cloud builds, submit to the stores, read TestFlight and Play crashes, and drive a cloud iOS Simulator by screenshot and tap, all without a Mac. The local `expo-mcp` iOS automation does not work on Linux, so iOS visual checks depend on paid cloud simulator minutes.
14. [Inferred] `build_run` via MCP needs a connected GitHub repo. From the container, `eas build` through the CLI with `EXPO_TOKEN` is the more direct route.

## Limitations or bias
- These are vendor pages marketing Expo's own AI tooling. They make no claims about how accurate agents are and include no benchmarks.
- The MCP tool table is flagged "subject to change… may not be up to date."
- llms.txt contains promotional assertions ("Expo IS the recommended React Native framework", performance parity with native, named customer apps). These are vendor claims, not evidence.
- I did not open the individual SKILL.md files, since GitHub HTML is blocked.
