## Learned points
1. [Documented] Method: the survey has run twice a year since Flutter 1.0 (2018). Q2 2026 had over 3,500 complete responses, collected through Flutter's IDE plugins (VS Code, IntelliJ, Android Studio), X, and the Flutter website. The sample is self-selected existing users.
2. [Documented] Overall satisfaction was 93% top-2 box (very + somewhat), flat vs Q4 2025. "Very satisfied" rose from 52% to 58% (stated as statistically significant) and "somewhat" fell from 40% to 35%. Trust in Flutter "to consistently meet your development needs" rose from 77% to 83%.
3. [Documented] Every measured subgroup (experience level, company size, team size, platform) reached at least 90% satisfaction, a first. The highest-rated areas were the Dart language (92%), Android app development (91%) and the core framework (90%).
4. [Documented] Novice vs expert: novice overall satisfaction reached 90% (+5 points), credited partly to the Feb 2026 "Dart and Flutter Getting Started" pathway. For the core framework alone it was 82% for novices vs 93% for experts, an 11-point gap that is "larger than almost any other split". The post says this signals "a steep learning curve that onboarding tutorials alone cannot solve". Novices also report lower AI-tool adoption, and Flutter is "exploring ways to surface AI-assisted Flutter guidance to novices earlier".
5. [Documented] Editor/agent usage was asked for the first time (multi-select): VS Code 66%, Android Studio 40%, Claude Code 32%, Antigravity 23%, GitHub Copilot 19%, Cursor 18%, Codex 17%, Zed 5%. Satisfaction (top-2): VS Code 88%, Claude Code 86%, Codex 85%, Zed 38%.
6. [Documented] Flutter's AI tooling as described: a Dart MCP server (shipped mid-2025); official Agent Skills for Flutter and Dart plus "agentic hot reload" launched at Google I/O; a Flutter Antigravity plugin; and work with "other major agentic tools to ensure Flutter plugins are available out of the box". Stated goal: Flutter as "a first-party, well-supported target for every major agentic coding tool", with investment in "core models, eval systems, and a combination of skills and MCP tools".
7. [Documented] Lowest-rated areas: Cupertino widgets 61% (down 6 points, the steepest decline in the survey), then Web 72%, Linux 73% and Windows 74% (all three improved). Respondents felt native-feeling iOS-style design "hadn't kept pace".
8. [Documented] Cupertino response: work on Cupertino was "intentionally paused" for decoupling. In the August release, the first step ships: `material_ui` and `cupertino_ui` packages on pub.dev, so design-system fidelity iterates outside core release cycles. Planned fidelity work includes Material 3 Expressive and Apple's Liquid Glass.
9. [Documented] Dissatisfaction themes: platform/ecosystem maturity 44% (upgrade pain, especially Android Flutter/Dart/Gradle/Kotlin/JVM version matrices), tooling/IDE 33%, bugs/stability 24% (debug tooling, e.g. stale breakpoints, confusing performance timeline; "we don't have a shipped fix"), UI/UX aesthetics 14%.
10. [Documented] Upgrade mitigations listed: 3.29 removed legacy script-based Gradle plugin application; 3.32 rewrote the Gradle plugin in Kotlin; 3.38 published an official Java/Kotlin/AGP/Gradle version matrix; 3.41 added AGP 9 support; 3.44 migrated to built-in Kotlin and made Swift Package Manager the default iOS/macOS dependency manager instead of CocoaPods, with 92 of the top 100 iOS plugins migrated.
11. [Documented] Governance and trust: trust in Flutter is 83% vs 62% in Google, a 20+ point gap across all company sizes. 98% know Google created Flutter. Canonical now leads the desktop roadmap. Over 70% of open PRs come from non-Google contributors. A four-tier Contributor Ladder (Contributor → Reviewer → Committer → Maintainer) was proposed after the survey closed.
12. [Documented] Only 71% agree Flutter is "proactive about technical issues and responsive to developer feedback", 10+ points below the other reliability and safety statements.
13. [Inferred] For this project: Claude Code is the most-used AI agent among Flutter respondents and highly rated (86%), and Flutter ships an MCP server and agent skills. Both support the Claude Code workflow. The weak Cupertino score suggests a Material-styled UI on iOS is the lower-risk path for a solo developer. The novice core-framework gap (82%) is a learning-curve signal for a beginner who leans on an agent.

## Limitations or bias
- First-party survey written by the Flutter team, which has an interest in positive framing. The sample is self-selected current users reached via IDE plugins and social media, so non-users and people who left are excluded.
- No confidence intervals or questionnaire wording given, apart from one "statistically significant" claim.
- Usage percentages are multi-select. "AI coding agent usage" shows tool popularity among Flutter users, not how well the agents perform on Flutter code.
