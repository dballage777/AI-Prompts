## Learned points
1. [Documented] Rename: "Expo services were formerly called EAS… EAS Build is now Expo Build, EAS Update is now Expo Update". The CLI (`eas`), `eas.json`, and the `eas` URL paths keep the old name (pricing.md).
2. [Documented] Expo Build is a hosted service that produces store binaries. `eas build --platform all` (or `android`/`ios`) builds both. It works for any React Native project, including ones made with `npx @react-native-community/cli init`, and "any native project". Android builds run on Linux runners in Google Cloud. iOS builds run on "macOS runners hosted in Expo's macOS cloud".
3. [Documented] iOS build pipeline: locally, EAS CLI prepares credentials, makes a tarball of the repo, and uploads it to a private GCS bucket. Remotely, each build gets "its own fresh macOS VM" with Xcode and Fastlane. That VM runs `npm install`, `npx expo-doctor`, restores credentials into a new keychain, runs `npx expo prebuild` (for CNG projects), runs `pod install`, then `fastlane gym`, and outputs `ios/build/App.ipa`. `package.json` hooks are available: `eas-build-pre-install`, `-post-install`, `-on-success`, `-on-error`, `-on-complete`.
4. [Documented] Signing: `eas build` offers to generate credentials and stores them on Expo servers. "Generating your iOS credentials (distribution certificate, provisioning profile, and push key) requires you to sign in with an Apple Developer Program membership." Once they exist, collaborators can start iOS builds with only an Expo account. Local credentials (`credentials.json`) are an alternative. `eas credentials` lets you inspect and change them.
5. [Documented] Submission without a Mac: "Expo Submit works on macOS, Linux, and Windows, so you don't need a Mac to ship iOS builds." The flow is `eas build --platform ios --profile production`, then `eas submit --platform ios`, or `--auto-submit` for both in one step. The build appears in TestFlight "usually 10-15 minutes" after upload. Final App Review submission happens in the App Store Connect web UI. "A paid Apple Developer account is required to submit apps to the Apple App Store."
6. [Documented] For non-interactive or CI submission (Expo Workflows, GitHub Actions), set up an App Store Connect API key with `eas credentials --platform ios`, or provide your own `ascApiKeyPath`/`ascApiKeyIssuerId`/`ascApiKeyId`, or an app-specific password. Also set `EXPO_TOKEN` and `ascAppId` in `eas.json`. Without a key, the CLI fails with "App Store Connect API Keys cannot be set up in --non-interactive mode." The manual fallback, if Expo Submit is down, requires a Mac with Xcode.
7. [Documented] The no-Mac iOS Simulator: "The iOS Simulator runs only on macOS. With Expo Simulators, the iOS Simulator runs on an Expo-hosted Mac, and you control it from any computer". The docs say it "also works in a cloud sandbox or for a background coding agent". The steps: create a build profile with `ios.simulator: true` (plus `developmentClient: true` for Fast Refresh), run `eas build … --non-interactive`, start Metro with a tunnel (`EXPO_UNSTABLE_TUNNEL_V2=1 npx expo start --tunnel`, the default from SDK 58), then `eas simulator:start --platform ios --type agent-device --build-id … --open-url …`. You view it through a browser preview URL or drive it with `eas simulator:exec`, agent-device, Argent, or Appium. Simulator builds are unsigned, so they need no credentials. Xcode is not needed.
8. [Documented] Development builds are the recommended path to the app stores, not Expo Go. A development build is "your own version of Expo Go where you are free to use any native libraries". The build method you pick decides where you can run it. Local `npx expo run:ios` builds work only on macOS, which is also the "only way to install a development build on an iPhone without a paid Apple Developer account". Cloud Expo Build from Linux or Windows supports Android, the iOS Simulator, and iPhone devices, with a note that "All builds that run on an iPhone device require a paid Apple Developer account for build signing." `eas build --local` for iOS still needs Xcode, so a Mac.
9. [Documented] You only rebuild native code after adding a native library, changing app config, or upgrading the SDK (`npx expo prebuild --clean`). Pure TypeScript/JavaScript changes only need `npx expo start`. When teammates' project fingerprints match, `eas build:dev` reuses an existing dev build.
10. [Documented] Continuous Native Generation (CNG): `android/` and `ios/` are "short-lived native projects… generated only when needed" from app config, a prebuild template, autolinking, and config plugins, via `npx expo prebuild`. Hand edits to the generated folders are lost on `--clean`, so customizations go in config plugins. CNG is "fully optional". The terms "eject" and "managed vs bare" are deprecated.
11. [Documented] Pricing, Free plan ($0/month): "15 Android and 15 iOS builds", low-priority queue (pricing notes "wait times of 90+ minutes" at peak), 45-minute build timeout, 5 concurrencies with at most 1 on macOS, 60 minutes of CI/CD Workflows, store submission, updates to 1K MAUs, Observe access, and no Simulators ("Coming soon"). The Expo MCP Server is "Fair use limited". The pricing text does not explicitly say the 15+15 builds reset monthly.
12. [Documented] Pricing, Starter plan ($19/month plus usage): $45 of build credit, high-priority queue, large workers, 2-hour timeout, 5 concurrencies with at most 2 on macOS, updates to 3K MAUs, and Simulators access (usage-based, "60 min/month included until 2027"). Production plan ($199/month plus usage): $225 credit, 15 concurrencies (10 on macOS), 50K MAUs, priority support, SSO. Enterprise is custom, from $1,000 of credit.
13. [Documented] Per-build overage rates: Android $1 (medium worker) or $2 (large); iOS $2 (medium) or $4 (large). Simulator minutes cost $0.10/min for iOS or Android, billed per second, with a 115-minute maximum session. CI/CD per-minute rates: Linux medium $0.018, macOS medium $0.075, macOS large $0.150. Maestro E2E test jobs cost $0.05 plus minutes. Expo Update overage on Starter is $0.005/MAU from 3,001 to 200,000. Hosting includes 100K requests, then $2 per 1M.
14. [Documented] Expo and the Expo SDK are MIT-licensed open source. Pricing applies only to the hosted services (pricing.md).
15. [Inferred] For a solo developer with no Mac, the full iOS path is covered by hosted services: cloud build, managed signing, Linux-run submit, and cloud simulator. The Apple Developer Program membership is the one non-Expo requirement for any device build, TestFlight, or store submission. (Apple's fee is not stated in these pages; take it from Apple.) If the store-submission fallback ever has to be manual, it needs a Mac.
16. [Inferred] On the Free tier, 15 iOS builds is thin for active iteration. Simulator access, which an agent in a Linux container needs to look at iOS UI, starts at Starter ($19/month). A realistic budget is Starter plus metered simulator minutes, plus the Apple membership. Android emulation also needs a local emulator, which a container may not support, or Expo Simulators' Android sessions.

## Limitations or bias
- Vendor docs and pricing describe a paid service favorably. They do not cover failure rates, real queue times, or debugging native iOS crashes without a Mac. The build intro table marks "Debugging native code locally" with ✗.
- I did not read the build "Limitations" page (https://docs.expo.dev/build-reference/limitations.md), which is linked from the intro.
- Expo Simulators is new: it is labeled "new" in the nav, Free tier is "Coming soon", and the "included until 2027" allowance is temporary. Prices and quotas may change.
- The `.md` pages contain embedded "AgentInstructions" blocks aimed at AI agents (for example, submitting docs feedback). I treated them as page data and ignored them.
