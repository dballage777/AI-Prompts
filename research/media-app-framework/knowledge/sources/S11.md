## Learned points
1. [Documented] expo-video lists platforms Android, iOS, tvOS, Web, and is "Included in Expo Go". The current docs are the SDK 58 reference, with recommended version ~58.0.14. Install with `npx expo install expo-video`.
2. [Documented] Background playback and Picture-in-Picture are build-time settings in the built-in config plugin (`plugins: [["expo-video", { "supportsBackgroundPlayback": true, "supportsPictureInPicture": true }]]`). The docs say these properties "cannot be set at runtime and require building a new app binary". On iOS they add `audio` to `UIBackgroundModes`. On Android, background playback adds foreground-service permissions and an expo-video foreground service, and PiP sets `android:supportsPictureInPicture`. Projects that don't use CNG must configure these by hand.
3. [Documented] PiP API: the `allowsPictureInPicture` and `startsPictureInPictureAutomatically` props, `startPictureInPicture()` / `stopPictureInPicture()`, the `onPictureInPictureStart/Stop` callbacks, and `Video.isPictureInPictureSupported()`. Only one player can be in PiP at a time. Each of these needs the config-plugin flag.
4. [Documented] Background playback: the `staysActiveInBackground` player property only works when `supportsBackgroundPlayback` is true. On Android, the now-playing notification also needs that flag.
5. [Documented] Fullscreen: the `fullscreenOptions` prop (`fullscreenOptions.enable`), `enterFullscreen()` / `exitFullscreen()`, and the `onFullscreenEnter/Exit` callbacks. Native controls are always on in fullscreen. On Android the JS runtime is paused in fullscreen, so `exitFullscreen` works only when called from a native listener.
6. [Documented] DRM: `DRMOptions` takes a `type` (`'clearkey' | 'fairplay' | 'playready' | 'widevine'`). Android supports ClearKey, PlayReady and Widevine. iOS supports FairPlay, with `certificateUrl` or `base64CertificateData`. Android also has a `multiKey` option.
7. [Documented] Streaming formats: `contentType` accepts `'auto' | 'progressive' | 'hls' | 'dash' | 'smoothStreaming'`. On iOS, an HLS source must have a `.m3u8` URI or `contentType: 'hls'`. A `headers` option sends request headers on Android and iOS.
8. [Documented] Caching: `useCaching: true` on a `VideoSource` turns on a persistent LRU cache (default 1 GB). The cache size is set with `setVideoCacheSizeAsync`, checked with `getCurrentVideoCacheSize` and cleared with `clearVideoCacheAsync`, and cached video plays offline. The cache does not work with HLS on iOS, and DRM-protected video is never cached.
9. [Documented] Other features: preloading (create a `VideoPlayer` before attaching a `VideoView`, or start with a `null` source and call `replace()`), local assets via `require`, media-library playback, and `createVideoPlayer` for players not tied to a component, which the developer must `release()` to avoid leaks. On Android, one `VideoPlayer` cannot be mounted in several `VideoView`s at once.
10. [Documented] An advanced iOS native extension point, `VideoAssetTransportProvider`, can intercept loading, for example to rewrite URLs or convert DASH to HLS. It "requires a custom native module, so it is not available in Expo Go. Use a development build instead."
11. [Documented] Known issue: two overlapping `VideoView`s with `contentFit="cover"` can render out of bounds on Android. The workaround is `surfaceType="textureView"`.
12. [Documented] The SDK 55 changelog (Feb 25, 2026) says "expo-av was removed from Expo Go because it has been replaced by expo-video and expo-audio. Additionally, expo-av is no longer receiving patches". In expo-video, `allowsFullscreen` was removed in favor of `fullscreenOptions.enable`. SDK 55 also deprecated expo-video-thumbnails (to be removed in SDK 56) in favor of `generateThumbnailsAsync` from expo-video.
13. [Documented] Other SDK 55 points: it ships React Native 0.83 and React 19.2. Legacy Architecture support is dropped, and the `newArchEnabled` option is removed. SDK 55 expo-video added `seekTolerance`, `scrubbingModeOptions` and bitrate fields, and refactored Android PiP to handle multiple VideoViews. `eas update` now requires `--environment`. Hermes v1 is opt-in, and the August 27 update reports memory and startup regressions on SDK 55 and recommends SDK 57.
14. [Documented] Expo Go positioning in SDK 55: "Expo Go is not recommended as a development environment for production apps". Developers are pushed toward development builds. Store releases of Expo Go lagged: the May 4 update said SDK 55 Expo Go was still awaiting App Store approval, and `eas go` can build an Expo Go for your own TestFlight.
15. [Documented] YouTube: the Expo docs index (llms.txt and llms-full.txt) has no YouTube page or guidance. Under "Voice and video" it lists only expo-video, VideoThumbnails and react-native-webview. react-native-webview is documented as "Included in Expo Go" (recommended version 14.0.1) and renders web content in a native view. The page has nothing specific to YouTube.
16. [Inferred] For trailers, expo-video covers direct MP4, HLS and DASH files that the app hosts or licenses. YouTube-hosted trailers are a separate problem: expo-video plays media URLs, not YouTube pages, and Expo's docs point only to WebView for web content. YouTube embedding terms would have to be checked in YouTube's own docs, not Expo's.
17. [Inferred] Because PiP and background playback need config-plugin changes, testing those features needs a development build made with EAS Build in the cloud, not Expo Go. That works without a Mac.

## Limitations or bias
- These are vendor docs. They describe capabilities, not performance or reliability. Known issues come from Expo itself.
- The "latest" reference is SDK 58, while the changelog is SDK 55. Some details may vary by SDK version.
- No YouTube-specific guidance exists on docs.expo.dev, so the YouTube point is about an absence, not a statement.
