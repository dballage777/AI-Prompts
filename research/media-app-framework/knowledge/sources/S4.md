## Learned points
1. [Documented] Flutter's official agent plugin bundles four capabilities. Agent skills are on-demand guides (layouts, state, widget tests). Agent rules are persistent instructions, for example triggering hot reload after editing widgets. The Dart and Flutter MCP server gives access to analyzer diagnostics, symbol resolution, test runners, and runtime inspection. Specialized agents include the Flutter Accessibility (a11y) agent.
2. [Documented] Claude Code setup: `claude plugin marketplace add flutter/agent-plugins`, then `claude plugin install dart-flutter@dart-flutter`, and verify with `claude plugin marketplace list`. The docs say that "Claude Code plugins discover skills and MCP servers, but don't automatically load plugin rules". To get the official rules, copy them from the flutter/agent-plugins `rules/` directory into the project's `CLAUDE.md`.
3. [Documented] Manual setup for other agents. MCP config: `{"mcpServers": {"dart": {"command": "dart", "args": ["mcp-server"]}}}`. Skills: `npx skills add flutter/agent-plugins --skill '*' --agent universal --yes` and `npx skills add dart-lang/skills --skill '*' --agent universal --yes`, installed into `.agents/skills`.
4. [Documented] The docs give setup tabs for these agents: Antigravity (Google's IDE/CLI, `agy`, configured in `.agents/mcp_config.json` or `~/.gemini/config/mcp_config.json`), Claude Code, Cursor (`/add-plugin dart-flutter`, `.mdc` rules in `.cursor/rules/`), Codex (`codex plugin add dart-flutter@dart-flutter`), GitHub Copilot (`.vscode/mcp.json`, `.github/copilot-instructions.md`), and Other (Windsurf, Zed, Cline).
5. [Documented] The Dart and Flutter MCP server runs locally over stdio and is part of the Dart SDK (`dart mcp-server`). Its capabilities: static analysis and fixes, symbol resolution, runtime introspection of a running app, pub.dev search and `pubspec.yaml` management, and running tests plus `dart format`.
6. [Documented] Version requirements from the pub.dev README: "all of the following set up instructions require Dart 3.9.0-163.0.dev or later". The `--experimental-mcp-server` flag "Can be removed for Dart 3.9.0 or later". The README also says: "WIP. This package is still experimental and is likely to evolve quickly." Runtime tools (hot reload, hot restart, runtime errors, widget inspector) "Require an active DTD connection" through the Dart Tooling Daemon. Some tools, such as app launch and management, are not enabled by default and are switched on with `--enable`.
7. [Documented] The Developer Knowledge MCP server is a separate, cloud-hosted Google service (developers.google.com/knowledge/mcp) for searching docs.flutter.dev, dart.dev and API references.
8. [Documented] Package skills: `dart run skills@ get` scans your direct dependencies in `pubspec.yaml` for packages that ship a `skills/` directory and installs the skills you select. `package:skills_lint` validates skills against the Agent Skills spec (agentskills.io).
9. [Documented] The Flutter a11y agent "is currently available in Google Antigravity" only. It checks semantic labels, 48x48 touch targets, contrast, and generates fixes.
10. [Documented] The docs' "When to use what" table: skill for multi-step recipes, Dart MCP for diagnostics, tests and runtime, Developer Knowledge MCP for live docs, package skill for library APIs, specialized agent for accessibility audits, rule for project conventions.
11. [Documented] Package skills are pitched as a fix for general models that "Suggest deprecated APIs or outdated syntax" and "Hallucinate APIs that don't exist in the specific version you're using".
12. [Inferred] Compared with Expo (S3), Flutter's agent tooling centers on a local SDK MCP server (analyzer, tests, hot reload). It has no hosted build, submit, crash, or cloud simulator tools. None of these AI pages mention iOS builds, signing, or working without a Mac, so a Linux-only Flutter project still needs a separate macOS CI or build service for iOS, sourced elsewhere.
13. [Inferred] In a Linux container, the Dart MCP server's static analysis and unit and widget tests work with no device. Runtime tools need a running app (DTD), which for iOS means a Mac. Android needs an emulator or device, and Flutter web or desktop Linux could stand in for some UI checks. That last point is my inference, not from these pages.
14. [Inferred] Google's own agent (Antigravity) gets features first, such as the a11y agent. Claude Code is supported but needs a manual step to load rules.

## Limitations or bias
- These are official docs about the framework's own tooling. They contain no evaluation of agent output quality.
- The pages favor Google's Antigravity, which appears first and is the only agent with the a11y agent.
- The standalone "AI rules" and "MCP server" pages named in the assignment now redirect to get-started. Their content is condensed into /ai/tools, so older detail (for example, a full rules file listing) may be gone. I did not read the rules files themselves, since GitHub HTML is blocked.
- The pub.dev README may be ahead of the stable SDK. I checked "3.9.0-163.0.dev" as stated on the page but did not confirm it against Flutter 3.50's bundled Dart version.
