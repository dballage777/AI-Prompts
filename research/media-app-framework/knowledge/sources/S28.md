## Learned points
1. [Documented] Maturity timeline: nightly preview releases of the Swift SDK for Android were announced 2025-10-24. Swift 6.3 nightly SDK previews followed in December 2025. Swift 6.3 (2026-03-24) "includes the first official release of the Swift SDK for Android". Swift 6.4 (2026-09-15) continued it, built against the LTS NDK 30. The current Getting Started guide installs `swift-6.4.3-RELEASE_android`.
2. [Documented] Scope is business logic, not UI. Quote: "The workgroup is not providing a single GUI solution". The prominent use case is "sharing core business logic, algorithms, and data models across applications". GUI options are left to "nascent community projects", which the workgroup "has not validated".
3. [Documented] How it works: Swift compiles to native machine code for Android, giving performance similar to NDK C/C++. Apps bundle a native Swift runtime (stdlib, Dispatch, Foundation). Android APIs are reached through Java or Kotlin over JNI, using swift-java's `jextract` (which gained a JNI mode in summer 2025) and `wrap-java` tools, or the low-level Swift Java JNI Core.
4. [Documented] App structure: Android apps are "typically written in Java or Kotlin". Swift modules are built as shared libraries per architecture, included in the .apk, and called from Kotlin or Java through swift-java. A real Swift-on-Android app therefore still needs a Kotlin/Java Android app shell and UI.
5. [Documented] Requirements: you cross-compile from a macOS or Linux host (the SDK is also bundled with the Windows installer). You need three components: an open-source Swift toolchain (installed with `swiftly install latest`; it must exactly match the SDK version, so Xcode's bundled Swift will not work), the Swift SDK for Android (`swift sdk install <artifactbundle URL> --checksum ...`), and Android NDK LTS r30 (`ANDROID_NDK_HOME`). Example build: `swift build --swift-sdk swift-6.4.3-RELEASE_android --triple aarch64-unknown-linux-android23 --static-swift-stdlib`, with `libc++_shared.so` pushed through adb.
6. [Documented] Swift 6.4: Android availability attributes in the runtime and packages through NDK 30. "Swift Build now supports Android in SwiftPM", which removes a post-install script. swift-java gained async/throwing support in protocol and callback wrappers, Runnable mapping for closures, and Java record types.
7. [Documented] Swift availability checks (`@available(Android 33, *)`, `#available(Android 33, *)`) now let one app target several Android API levels. This was not supported until late 2025.
8. [Documented] Known gaps as of December 2025: debugging was "now a high priority", because it "may work for small examples" but needs IDE integration (sourcekit-lsp and the debugger in VS Code or Android Studio). Running tests in an Android emulator through the official GitHub workflow was "underway". The swift-java interop was still "ongoing" work.
9. [Documented] Ecosystem: over 25% of Swift Package Index packages built for Android at announcement time (Oct 2025), and the Community Showcase marks Android compatibility. Production users (with homegrown interop) include Spark email, flowkey, MediQuo, and Naturitas, apps "collectively downloaded millions of times".
10. [Documented] Governance: the Android workgroup is an open group under the Swift Platform Steering Group. Its chartered goal is to make Android "an officially supported platform", including CI in PR checks, a defined range of supported API levels, and debugging support. Members include Apple-affiliated and community contributors (for example, Skip.dev's Marc Prud'hommeaux wrote the Getting Started guide). It meets biweekly.
11. [Inferred] For this project, the Swift SDK for Android does not offer a shared-UI path. You would still write a Kotlin/Compose Android UI plus a SwiftUI iOS UI, and share only a Swift core. Its tooling (Linux-hosted cross-compile) is Mac-free for Android. The iOS half would still need Xcode on macOS (Mac or CI) for store builds. For a solo developer this is more moving parts than KMP or Flutter, and debugging support is still immature.
12. [Inferred] Since the official release in Swift 6.3, the SDK is viable for shipping shared logic, but it is about 8 months old as an official release (as of Nov 2026). Expect fewer agent-ready examples and docs than for KMP, Flutter, or RN.
