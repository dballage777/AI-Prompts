## Learned points
1. [Reported] (vendor comparison) Architecture framing: Flutter's Impeller renderer compiles shaders at build time (GLSL 4.60 to SPIR-V to Metal or Vulkan, about 100KB per architecture), which removes first-run shader jank. The post says Impeller became mandatory on iOS in Flutter 3.29. React Native's New Architecture (JSI + Fabric + TurboModules) replaces the JSON bridge with synchronous C++ calls. It became the default in RN 0.76 (Oct 2024), and the legacy architecture is frozen and scheduled for removal.
2. [Reported] (vendor) Rendering trade-off: RN maps `<View>/<Text>/<Image>` to native UIView/TextView etc. The post says this makes RN apps sensitive to changes in each OS release. Flutter draws every pixel itself and depends only on Metal, Vulkan, or GLES. The post claims Flutter teams "primarily track framework updates on a predictable quarterly cycle". It cites Shopify's 2025 New-Architecture migration problems as examples: state batching, tap failures from shadow-tree manipulation, and view flattening removing components with refs.
3. [Reported] (vendor, uncited figures) The post offers several numbers without reproducible sources: "20% lower long-term maintenance" for Flutter (attributed to Forrester 2024); "20-33% annual savings" after switching RN to Flutter; RN's talent pool "20x larger"; ramp-up of 1-2 months on RN vs 2-3 months on Flutter for web teams; code sharing of 85-95% for Flutter vs 80-90% for RN; Flutter at 46% vs RN at 35% share (Statista); Flutter developers earning about 7% more. Treat all of these as marketing claims.
4. [Reported] (vendor) Performance: citing an unnamed "detailed 2025 benchmark", the post says all stacks (Flutter, RN, native) reach first frame in under ~50 ms. It says Flutter has the fastest first frame, steadier frame pacing at 60 and 120 Hz, and a more stable memory footprint, while RN may need iOS-specific tuning. Its conclusion is that "both frameworks perform well".
5. [Reported] (vendor) OTA updates: Microsoft CodePush was retired on 2025-03-31, which leaves Expo EAS Update as the main maintained RN OTA solution. Expo normally downloads full JS bundles plus new assets, and its bundle diffing is "in beta". The post says neither framework can update native code, framework versions, or native dependencies over the air.
6. [Reported] (vendor) Ecosystem: Flutter has a "complete SDK" with Material 3, Cupertino, and first-party camera, maps, webview, and storage packages, plus Firebase plugins. Partners: Codemagic (CI with Apple Silicon machines and automatic code signing), Shorebird, Serverpod, Very Good Ventures. RN "increasingly relies on Expo" (which RN docs recommend by default), with 50+ maintained native modules and EAS cloud build, submit, and update. The post notes that "Expo SDKs trail React Native releases by weeks, and EAS pricing scales with usage".
7. [Reported] (vendor conclusion) "For new projects without existing team expertise, Flutter's trajectory ... increasingly favor it as the default choice". For teams that already know React or JS, "React Native with Expo remains highly productive and now performs 'good enough'".
8. [Documented] (Shorebird docs on its own product) How code push works: apps are built with Shorebird's fork of Flutter. Its modified engine checks for Dart patches on startup in a background thread, and a patch applies on the next launch. Patches can change any Dart code, including pure-Dart packages. Native code (Kotlin/Java/Swift/ObjC), assets, Flutter version changes, and new native plugins all require a new store release. `shorebird patch` detects native or asset diffs and warns, or stops in CI.
9. [Documented] (blog, describing own tech) On iOS, changed code runs in a custom Dart interpreter. The blog says "98%+ of code (including the Flutter framework itself) runs at full native CPU speed", while changed code runs "approximately 100x slower". Patches are diffs against the release, not against the previous patch.
10. [Documented] (Shorebird FAQ) Store-compliance claim: for Google Play, Shorebird cites the Device and Network Abuse policy exception for "code that runs in a virtual machine or an interpreter". For Apple, it cites Developer Program License Agreement §3.3.1(B) on downloaded interpreted code. The conditions are: it must not change the app's primary purpose, not bypass signing, sandbox, or security, and not create a storefront. The blog cites App Review Guideline 2.5.2 for both Shorebird and Expo. Shorebird says that keeping patch *content* compliant "remains your responsibility". It says deliberate misuse breaks its Terms of Service, and it says nothing stronger than "complies" (no Apple endorsement is claimed).
11. [Documented] (FAQ) Limitations relevant to testing: patches do not install on the iOS Simulator, because the interpreter is built for physical arm64 devices ("Test iOS patches on a physical device"). Android emulators work. Shorebird is active only in release builds, not debug or profile. Only stable Flutter releases are supported: quarterly minors are added within 5 business days and patch releases within 1 business day. You cannot use your own Flutter fork.
12. [Documented] (FAQ/release docs) Shorebird does not submit to stores. `shorebird release ios` wraps `flutter build ipa` and then tells you to upload through Xcode's Distribute App, the macOS Transporter app, or `xcrun altool --upload-app ... --apiKey`. CI is supported with a `SHOREBIRD_TOKEN` (service account) on GitHub, GitLab, Codemagic, Fastlane, or generic CI.
13. [Inferred] The iOS release steps use `flutter build ipa` and `xcrun`, so building and uploading an iOS release with Shorebird still needs macOS, either locally or on a hosted macOS CI runner such as GitHub Actions macOS or Codemagic. From a Linux container, you can create Android releases and patches locally. For iOS you would trigger a macOS CI job. The docs do not say this in one sentence; it follows from the commands shown.
14. [Documented] (pricing page, 2026) Hobby $0 (5,000 patch installs per month); Pro $20 per month or $240 per year (50,000 per month); Business $400 per month or $4,800 per year (1,000,000 per month, overage $1 per 2,500 installs); Enterprise custom. Every plan includes unlimited apps and releases, rollbacks, signed patches, staging, an MCP server, and CI service accounts.
15. [Documented] (AI apps docs) Shorebird has a read-only remote MCP server at `https://mcp.shorebird.dev/mcp` with OAuth sign-in. For Claude Code: `claude mcp add --transport http shorebird https://mcp.shorebird.dev/mcp` then `/mcp` to sign in. It can answer release, patch, and rollout questions. It cannot publish, roll back, or delete.
16. [Documented] (FAQ) If you cancel, devices keep the last patch they received and the account drops to Hobby. Sign-in is Google or Microsoft accounts only.
17. [Inferred] For this solo, no-Mac project, Shorebird is the Flutter counterpart to EAS Update. It is cheap at small scale (free tier of 5,000 patch installs per month). It does not remove the need for macOS for iOS store builds, and iOS patch testing needs a physical iPhone.

## Limitations or bias
- Strong vendor bias: Shorebird's business depends on Flutter adoption ("Built for Flutter, by the people who made Flutter"; its CEO, Eric Seidel, writes most of the blog). The comparison ends with a Shorebird call to action.
- Many statistics are uncited or loosely cited (Forrester 20%, "case studies", Statista share, salary gap, an unnamed "2025 benchmark"). Do not reuse them as facts.
- The store-compliance statements are Shorebird's own reading of Apple and Google policy, not a ruling by either store.
- The Shopify migration examples are cited second-hand.
