## Learned points
1. [Documented] The iOS release guide opens by requiring a Mac: "Xcode is required to build and release your app. You must use a device running macOS to follow this guide." Publishing also requires enrollment in the Apple Developer Program.
2. [Documented] The manual release flow needs Xcode at several points. You open `ios/Runner.xcworkspace` to check the Bundle Identifier, signing ("Automatically manage signing" is on by default, and you pick the Team) and the iOS Deployment Target. You also replace the icons and launch image in `Assets.xcassets`.
3. [Documented] You build with `flutter build ipa`. It writes an `.xcarchive` to `build/ios/archive/` and an `.ipa` to `build/ios/ipa`. Options include `--obfuscate`/`--split-debug-info`, `--export-method ad-hoc|development|enterprise`, `--build-name`/`--build-number`, and `--export-options-plist`. The version lives in `pubspec.yaml` as `version: 1.0.0+1`, and every upload needs a unique build number.
4. [Documented] There are three ways to upload: the Apple Transporter macOS app; `xcrun altool --upload-app --type ios -f build/ios/ipa/*.ipa --apiKey ... --apiIssuer ...`; or Xcode's Validate App and Distribute App. All three are macOS tools. After upload, expect an email within 30 minutes saying the build is validated and ready for TestFlight.
5. [Documented] There is a documented alternative using Codemagic CLI tools: `pip3 install codemagic-cli-tools` plus an App Store Connect API key with App Manager access (issuer ID, key ID, .p8 file). The tools can create the iOS Distribution certificate from a private key (`app-store-connect fetch-signing-files ... --create`), keep signing files in a temporary keychain (`keychain initialize`/`keychain use-login`), run `xcode-project use-profiles`, run `pod install`, build `flutter build ipa --release --export-options-plist=...`, and publish with `app-store-connect publish`. The `keychain`, `xcode-project` and `pod install` steps imply a macOS host.
6. [Documented] After upload, TestFlight internal testing and App Store submission (Pricing and Availability, "1.0 Prepare for Submission", Submit for Review) happen in the App Store Connect web UI. No Mac is needed for these steps.
7. [Documented] Setting up iOS development means installing the latest Xcode, then `xcode-select -s ... && xcodebuild -runFirstLaunch`, `sudo xcodebuild -license`, `xcodebuild -downloadPlatform iOS` (simulator runtimes) and CocoaPods for plugins with native code. Every step is macOS-only.
8. [Documented] Running on a physical iPhone means connecting it by USB "to the USB port on your Mac", trusting the computer, turning on Developer Mode and installing a signed development certificate. A free personal Apple account is enough for testing on a device. Deploying to the App Store needs the paid program ("upgrade your personal Apple Developer account to a professional account").
9. [Documented] The simulator is "renamed to Device Hub on Xcode 27" (`open -a DeviceHub`). On Xcode 26 or earlier you use `open -a Simulator`.
10. [Documented] The CD page names three all-in-one CI/CD services with built-in Flutter support: Codemagic, Bitrise and Appcircle. It also covers fastlane with GitHub Actions, Cirrus, Travis, GitLab and CircleCI. It recommends testing builds locally before moving to the cloud, and says to "Shard your script to run on both Linux and macOS platforms". For iOS you "might have to specify a dependency on Xcode".
11. [Documented] For CI signing, the CD page uses `flutter build ios --release --no-codesign --config-only` and then fastlane. It recommends fastlane Match "to synchronize your certificates across machines". Secrets go in encrypted CI variables, which you can pass with `--dart-define`. It warns not to echo them back in logs.
12. [Documented] Some of the fastlane local-setup steps need a Mac: `open [project]/ios/Runner.xcworkspace/` and pick the distribution certificate, or `brew install fastlane`. Setting `FASTLANE_PASSWORD` for "iTunes Connect" is also part of the flow.
13. [Documented] Using Xcode Cloud with Flutter requires Xcode 13.4.1 or higher plus Apple Developer Program enrollment. A `ios/ci_scripts/ci_post_clone.sh` script installs Flutter with git (`flutter precache --ios`, `flutter pub get`) and CocoaPods with Homebrew. You create the workflow in Xcode ("Product > Xcode Cloud > Create Workflow"). Build numbers start at 1 unless you set "Next Build Number".
14. [Documented] Supported platforms as of Flutter 3.50: iOS (Arm64) is supported on 15 to 27 and CI-tested on 18 and 26; iOS 14 and earlier are unsupported. Android is supported on API 24 to 37. The page also warns that "macOS Tahoe (26) is the last release for Intel-based Macs. macOS Golden Gate (27) requires Apple Silicon."
15. [Documented] The pages disagree on the minimum iOS version. The release guide (last updated 2026-07-31) still says "Flutter supports iOS 13 and later", but the supported-platforms page (last updated 2026-11-11) lists iOS 15 to 27 as supported.
16. [Documented] The install hub recommends installing with the VS Code Flutter extension and links per-platform setup for Android, iOS, web, Windows, macOS and Linux. The iOS setup page is written for Xcode on a Mac. None of these pages describes iOS builds from Linux.
17. [Inferred] For a Linux container with no Mac, Flutter's official docs offer no local iOS build path. The usable no-Mac route is a hosted macOS CI (Codemagic, Bitrise or Appcircle, or GitHub Actions macOS runners with fastlane), with signing done by API key and Match or Codemagic CLI. Xcode Cloud is a weaker fit because the first workflow is created in Xcode. Running on a physical iPhone or the simulator still needs a Mac (local or rented).
18. [Inferred] A Linux machine can do Android builds (`flutter build appbundle`) and fastlane `supply` uploads to Play, so Android work can happen entirely in the container.

## Limitations or bias
- These are Flutter's own docs. They describe the official path, not every workaround (for example, they never mention renting cloud Macs).
- The CD page is dated: it mentions "iTunes Connect", `osx_image: xcode9.2` and Travis. Its CI examples may not match current services.
- The iOS release guide and the supported-platforms page disagree on the minimum iOS version (13 vs 15).
- The supported-platforms table was stripped from the `.md` copy, so I read it from the HTML. The cells came through as concatenated text, and I read them as "Supported 15 to 27 / CI tested 18 and 26 / Unsupported 14 and earlier".
