## Learned points
1. [Documented] In 0.76 (Oct 2024) the New Architecture became the default. It is a ground-up rewrite that started in 2018: Fabric renderer, TurboModules, no bridge, lazy module loading, React 18 concurrent features. An automatic interop layer supports old-architecture libraries. The post says "More than 850 libraries are already compatible, including all libraries with over 200K weekly downloads", and you can check compatibility at reactnative.directory.
2. [Documented] 0.82 (Oct 2025) is "the first React Native that runs entirely on the New Architecture". Setting `newArchEnabled=false` or `RCT_NEW_ARCH_ENABLED=0` is ignored. RN 0.81 and Expo SDK 54 are "the last versions that allow you to use the Legacy Architecture". Interop layers stay "for the foreseeable future", and libraries that support both architectures keep working.
3. [Documented] 0.82 also shipped an experimental opt-in to Hermes V1, which required building from source. On Expensify it measured bundle load 3.2% faster on low-end Android and 9% faster on iOS, and Total TTI 7.6% faster on Android and 2.5% on iOS. Other 0.82 items: React 19.1.1, DOM-like Node APIs on refs, Web Performance APIs (canary only) and a `debugOptimized` Android build type (about 20 FPS in `debug` vs about 60 FPS, backported to 0.81 and Expo SDK 54). Breaking changes: uncaught promise rejections now raise `console.error`, Gradle 9.0.0, and some private API moves. The release had 868+ commits from 93 contributors.
4. [Documented] 0.83 (Dec 2025): React 19.2, new DevTools features, Web Performance and IntersectionObserver APIs (canary). It is "the first React Native release with no user facing breaking changes". It went into Expo SDK 55, planned for January 2026.
5. [Documented] 0.84 (Feb 2026): Hermes V1 became the default JS engine on iOS and Android with "No migration required". Precompiled iOS binaries (`.xcframework`) are now the default, "significantly reducing build times for iOS apps". Legacy Architecture code is compiled out of iOS builds by default (`RCT_REMOVE_LEGACY_ARCH`), several Android legacy classes were removed, Node.js v22.11 or later is required, and the version ships React 19.2.3 and supports HEIC/HEIF images.
6. [Documented] 0.85 (Apr 2026): a New Animation Backend (written with Software Mansion). Breaking changes: the Jest preset moved to `@react-native/jest-preset`, Node below v20.19.4 was dropped (Node 21 and 23 are not supported), and `StyleSheet.absoluteFillObject` was removed. Expo SDK 56 includes 0.85.
7. [Documented] 0.86 (Jun 2026) has "no user-facing breaking changes" (the second such release). It includes Android 15+ edge-to-edge fixes and DevTools light/dark emulation. Governance changed: the RN repository, along with React, Metro, Yoga and the website, moved from the `facebook` GitHub org to `react`, which "reflects the transition of React and React Native to the React Foundation, an independent foundation dedicated to the long-term stewardship of the React ecosystem."
8. [Documented] 0.87 (Aug 2026) had intentional breaking changes. The Strict TypeScript API became the default, and the JS API is now scoped to root exports ("From 0.87, React Native's JS API changes only when we intend it to."). It also introduced experimental Swift Package Manager support and raised the minimum toolchain to Node.js 22, Android Gradle Plugin 9 and Kotlin 2.0+ (Kotlin 2.2.0 bundled). The post says "Many apps should be able to upgrade to 0.87 with few or no errors."
9. [Documented] 0.88 (Oct 2026) has "no user-facing breaking changes", the third after 0.83 and 0.86. It adds Web-based (W3C EventTarget) event dispatching by default, variable fonts (`fontVariationSettings`), iOS SceneDelegate/UIScene lifecycle support (the template moves the entry point to `SceneDelegate`), ArrayBuffer for Java TurboModules, React 19.3.0 and Metro 0.87. It had 568 commits from 91 contributors. Expo SDK 58 will carry it.
10. [Documented] The posts give an iOS build-tool roadmap: 0.87 adds experimental SwiftPM, 0.88 hardens it, and 0.89 targets "Swift Package Manager as the default, with an opt-out to CocoaPods". "We plan to remove CocoaPods support in a later release of React Native."
11. [Documented] Every release post ends with the support window: "0.82 ... 0.79.x moves to unsupported", "0.84 ... 0.81.x moves to unsupported", "0.88 ... 0.85.x moves to unsupported". That means three minor series are supported at a time (see S9).
12. [Documented] Summary of which releases have breaking changes. Releases labeled "no breaking changes" or "no user-facing breaking changes": 0.83, 0.86, 0.88. Releases with breaking changes listed: 0.82, 0.84 (Node 22, legacy classes removed, RCTImage observer change that may affect `react-native-svg`), 0.85 and 0.87.
13. [Documented] Expo is woven into RN's release process. Expo engineers co-author every post from 0.82 to 0.88, and each post says which Expo SDK carries the release. New RN versions first appear in `expo@canary`, so an Expo SDK lags the RN stable release by weeks to months (for example, 0.83 in Dec 2025 went into SDK 55 in Jan 2026).
14. [Documented] Other platforms: the blog index includes "React Native Comes to Meta Quest" (2026-02-24, Callstack), and the 0.76 post thanks Expo, Software Mansion and Callstack for migrating key libraries.
15. [Inferred] For long-term maintenance, RN ships a minor version about every two months. The 2025–2026 trend is toward fewer breaking changes: three no-breaking releases, the stable Strict TS API, and foundation governance. Even so, real churn remains in toolchain minimums (Node, AGP, Kotlin) and the coming CocoaPods to SwiftPM switch. A solo developer on Expo picks these up through Expo SDK upgrades instead of directly.
16. [Inferred] Precompiled iOS binaries (0.84) and SwiftPM mostly speed up builds on a Mac or on cloud macOS builders. They do not remove the need for macOS to build iOS. None of these posts describes building for iOS from Linux.

## Limitations or bias
- This is the project's own blog, so it is upbeat. "No user-facing breaking changes" follows RN's own definition (see S9's versioning policy) and does not cover third-party library breakage.
- The performance numbers (Hermes V1, debugOptimized) come from a few chosen apps or demos.
- The 0.88 post says React 19.3.0 is synced, but the Branches table (S9) lists React `19.2.3` for 0.88-stable. That is a possible docs inconsistency.
- Blog dates and the release-table dates differ by a few days (for example, the 0.88 blog is dated Oct 19 but the table shows 2026-10-15).
