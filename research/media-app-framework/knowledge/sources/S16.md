## Learned points
1. [Documented] Expo: RevenueCat requires an Expo **development build** (`npx expo install expo-dev-client`) to use and test purchases; supported on Expo SDK 54 or later. Packages: `react-native-purchases` (core) and `react-native-purchases-ui` (Paywalls, Customer Center), installed with `npx expo install react-native-purchases react-native-purchases-ui`.
2. [Documented] After installing the SDK on Expo you must run a full native build; hot reloading without rebuilding gives errors such as "Invariant Violation: `new NativeEventEmitter()` requires a non-null argument."
3. [Documented] Expo Go: native IAP modules do not run in Expo Go, but `react-native-purchases` has a built-in **Preview API Mode** that auto-detects Expo Go and swaps native calls for JavaScript mock APIs, so subscription UI and flows load without errors; real purchases do not work and full testing requires a development build.
4. [Documented] RevenueCat's Expo test path uses EAS: `npm install -g eas-cli`, `eas login`, `eas init`, `eas build:configure`; iOS simulator via an `ios-simulator` profile (`"ios": {"simulator": true}`) and `eas build --platform ios --profile ios-simulator`; Android via `eas build --platform android --profile development`, answering "Yes" to create a new Android Keystore; Android devices can be loaded via Expo Orbit or QR code.
5. [Documented] Test Store: RevenueCat's built-in test environment "works immediately without platform setup" — no App Store Connect or Google Play setup needed; uses a separate Test Store API key; purchases show a modal with buttons to simulate success, failure, or cancel; they update `CustomerInfo`, grant entitlements, and appear in the dashboard as sandbox data. A Test Store is auto-created with products for new projects.
6. [Documented] Test Store minimum SDK versions: iOS 5.43.0, Android 9.9.0, Flutter 9.8.0, React Native 9.5.4, Capacitor 11.2.6, Cordova 7.2.0, Unity 8.3.0, KMP 2.2.2, Web (JS) 1.15.0. Test Store products cannot be edited after save (create a new product to change price/duration).
7. [Documented] Test Store keys crash release builds on purpose (iOS builds without `DEBUG`, Android non-debuggable builds). TestFlight and Google Play internal/closed/open testing tracks are release builds, so testing there requires the platform API key and the platform sandbox. Opt-out: `forceAllowTestStoreInReleaseBuilds` (iOS SDK 5.89.0+, Android SDK 10.21.0+) only for internal builds never uploaded to stores.
8. [Documented] Flutter prerequisites: Flutter 3.22 or later; Android needs Kotlin 2.1.0+ and compileSdk 35+; packages `purchases_flutter` and `purchases_ui_flutter` (example pin `^10.10.0`) via `flutter pub add`. iOS: new Flutter projects resolve native deps with Swift Package Manager automatically; with CocoaPods you must set `platform :ios, '13.0'` (iOS 13.0+ required) and Swift 5.0+.
9. [Documented] Flutter Android: RevenueCat Paywalls require `MainActivity` to subclass `FlutterFragmentActivity` instead of `FlutterActivity`; purchase Activity launchMode must be `standard` or `singleTop` (new Flutter projects default to `singleTop`, which is safe).
10. [Documented] React Native (bare) prerequisites: React Native 0.80 or later; `npm install --save react-native-purchases react-native-purchases-ui`; autolinking, CocoaPods installed automatically on first run. New React Native projects default the main Activity to `singleTask`, which "can cancel purchases" (e.g., when Google Play sends the user to a banking app) — must change to `standard` or `singleTop`.
11. [Documented] RN Android may hit R8 build failures with `react-native-purchases-ui` from an older AGP bug; documented fix forces `com.android.tools:r8:8.1.44` in project-level build.gradle.
12. [Documented] Upcoming breaking change: RevenueCat React Native/Expo SDK v12 and Flutter SDK v12 will require Swift Package Manager for iOS dependencies; SPM support in React Native and Expo is "currently experimental"; CocoaPods instructions apply to SDK 11. If building with Xcode 27 on Expo SDK 56 or earlier, a Podfile post_install hook (via config plugin) is needed.
13. [Documented] Do not add the RevenueCat iOS SDK (`purchases-ios` / `purchases-ios-spm`) separately in RN/Expo/Flutter — it is bundled; adding it causes duplicate-package/version conflicts.
14. [Documented] Enabling the In-App Purchase capability "in Xcode" is described as a step for App Store distribution; "Nothing else is needed to build and test with the Test Store."
15. [Documented] Web: the RN/Expo SDK supports web via RevenueCat Billing (Stripe as processor); Flutter web supports RevenueCat Billing, Stripe Billing, or Paddle Billing. On web, `getProducts`, `purchaseProduct`, `restorePurchases` do not work; Flutter web cannot present RevenueCat Paywalls yet. Web products are configured separately but can share entitlements; use the same appUserID across platforms.
16. [Documented] Dashboard model: Project → store connections (Apple, Google, Web, etc.) → Products → Entitlements → Offerings → Paywalls (remotely configurable without app updates). Subscription status is checked via `Purchases.getCustomerInfo()` and `customerInfo.entitlements.active[...]`.
17. [Documented] Pricing (Pro plan): free up to $2,500 monthly tracked revenue (MTR); then 1% of tracked revenue (example: $25 at $2.5K MTR). MTR is measured in USD before the platform (Apple/Google) cut and includes subscriptions, renewals, one-time purchases. No charge in months below the threshold. Credit card optional at sign-up, but at $2.5K MTR without a card "parts of the product will become unavailable." RevenueCat is not a payment processor; Apple/Google/Stripe still pay you. Old Pro plan was 1.2%. Enterprise is custom.
18. [Documented] RevenueCat docs offer `llms.txt` and a Markdown version of each page explicitly for AI agents, plus an "Ask Rico" AI assistant and an "AI Toolkit" section in the nav.
19. [Inferred] For a no-Mac solo build: the Expo path can be done entirely through EAS cloud builds (simulator build for iOS, dev build + keystore for Android), and the Test Store lets subscription logic be developed before App Store Connect / Play Console products exist. However, real App Store sandbox testing goes through TestFlight with the Apple key; the "enable In-App Purchase capability in Xcode" step is phrased for Xcode users, so the no-Mac equivalent (capability via EAS/App Store Connect) needs confirming from Expo docs, not this source.
20. [Inferred] Flutter requires a few hand edits to native Android files (MainActivity superclass, launchMode) that Claude Code can do from Linux; bare RN requires the launchMode fix; Expo's managed config handles most of this but the docs do not explicitly say whether Expo's default launchMode is safe.
