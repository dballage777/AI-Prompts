## Learned points
1. [Documented] Expo's "three tools" for AI-built apps: (a) Skills — `SKILL.md` instruction folders, loaded on demand, low context cost; official set at expo.dev/skills and the `expo/skills` repo, work with Claude Code, Cursor, Codex; (b) MCP — the Expo MCP server for EAS builds, workflows, logs, and simulator control; (c) context discipline — keep each thread under ~50% of the context window and branch per task (plan → stack → build → bug).
2. [Documented] "Claude Code users can enable the Expo plugin that bundles skills and MCP." Docs give the Claude Code install command: `claude mcp add --transport http expo https://mcp.expo.dev/mcp`, then `/mcp` to authenticate. Expo MCP is also in Claude Connectors (web/desktop/mobile). There is no separate "Expo Agent" product; Expo also publishes `docs.expo.dev/llms.txt`.
3. [Documented] Advice: run `npx expo-doctor` before asking an agent to debug a failing build; MCP tool definitions are token-heavy, so add an MCP only for services the project uses.
4. [Documented] MCP launch (Oct 2025) was a preview "available to all Starter Plan, Production Plan, or Enterprise Plan subscribers" (any EAS paid plan). Current docs list only "An Expo account is required," but mark `search_documentation` as "requires an Expo Services paid plan" and `simulator_start` as "a billed cloud simulator session." [Inferred] Access terms appear to have loosened since launch; exact free-tier coverage should be checked on expo.dev/pricing.
5. [Documented] Server capabilities (current docs): read/search docs, trigger and monitor EAS builds (`build_run` requires a GitHub repo connected to the project), `build_submit` to App Store / Play Store, workflow runs/logs, TestFlight crashes and feedback, App Store and Play reviews (reply requires confirmation), Play crash/ANR data, Expo Observe performance metrics and errors, Sentry issues, usage budgets.
6. [Documented] Cloud simulators via MCP: `simulator_start` starts a billed cloud simulator session; `automation_tap`, `automation_take_screenshot`, `automation_find_view`, `automation_type`, `automation_scroll` can target a cloud simulator session; idle sessions stop after 10 minutes by default; a dashboard URL lets you view the device.
7. [Documented] Local capabilities need Expo SDK 54+, the `expo-mcp` package, and a running local dev server: screenshots, taps, DevTools, `collect_app_logs` (logcat / iOS syslog), Expo Router sitemap. Limitations: one dev server at a time; iOS local capabilities are simulator-only and "only available on macOS hosts."
8. [Inferred] For a Linux container without a Mac: Expo MCP server-side tools (EAS build, submit, logs, TestFlight crashes) work from anywhere; iOS visual verification would need the billed cloud simulator, not local tools; Android local capabilities are not stated as macOS-restricted, but running an Android emulator inside a cloud container is a separate question.
9. [Documented] Expo's position on agents vs native: "Agents reduce typing cost on both paths"; Expo still wins with one TypeScript app plus EAS Build/Update/Submit; "Dual native still wins when shared UI is thin or the org requires separate stacks."
10. [Reported] Solo dev case (guest author on Expo's blog): built "Wellspoken" for iOS and Android in a one-week target with React Native + Expo SDK 54, TypeScript, OpenAI via LangChain, AssemblyAI, RevenueCat for subscriptions, EAS Build/Update/Submit. Claims: "I never opened Xcode / Android Studio once"; EAS handled provisioning profiles, signing certificates and keystores automatically.
11. [Reported] Same case: used expo-audio, expo-camera (60-second video recording), expo-video (playback with `useVideoPlayer`), expo-notifications (Expo push service routes to APNs/FCM), expo-secure-store (Keychain / EncryptedSharedPreferences), expo-apple-authentication (~30 minutes), expo-file-system uploads to S3.
12. [Reported] Same case: an onboarding bug fixed and shipped via EAS Update in 15 minutes instead of a 2–3 day store review; separate preview and production update channels. Early metrics after a month: 400+ users, $500+ revenue, first paying customer within 24 hours.
13. [Reported] Same case, lessons: shipped with no automated tests and "already shipped a few regression bugs that tests would have caught."
14. [Inferred] The case study is close to this project's shape (subscription paywall via RevenueCat, video playback, LLM calls through a backend, solo dev, no Xcode), which supports the Expo path being feasible without a Mac, but it is a single self-reported success story published by the vendor.
