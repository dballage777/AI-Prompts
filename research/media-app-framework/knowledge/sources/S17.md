## Learned points
1. [Research] Preprint compares five implementations of the same plant-management app ("ChloroByte"): native iOS, native Android, Flutter, React Native, Kotlin Multiplatform (KMP) — eight runtime variants across Android and iOS — guided by ISO/IEC 25010. Shared Fastify/TypeScript backend with PostgreSQL and S3-compatible storage.
2. [Research] Devices: iPhone 15 (iOS 26.3.1; 26.6.1 for the React Native rerun) and Pixel 6 Pro (Android 16). Stacks: React Native via Expo 55, RN 0.83, React 19, TypeScript 5.9, Hermes, New Architecture; Flutter with http, sqflite, flutter_secure_storage; native iOS SwiftUI + GRDB + NukeUI; native Android Compose + Room + OkHttp + Coil; KMP with Kotlin 2.0.0, Ktor 2.3.12, SQLDelight 2.0.2 and native Compose/SwiftUI shells (shares services, not UI). Flutter SDK version not stated in the text read.
3. [Research] Workload: 12-step benchmark (login, backend reset, seed 200 plants, fetch page of 50, ETag 304 check, image download, image decode, render 50-row list, scroll 200-row list, 200-record local sync, upload); 2,000 sequential runs per variant = 16,000 completed runs, all 12/12 steps successful.
4. [Research] Primary metric (seven non-UI client operations, sum of means): iOS — native 353 ms, KMP 375 (+6.1%), Flutter 519 (+46.9%), React Native 679 (+92.4%). Android — native 453 ms, KMP 505 (+11.4%), React Native 1,218 (+169.0%), Flutter 1,547 (+241.7%). No implementation led every individual operation.
5. [Research] Full-scenario mean elapsed time (contextual, includes backend and UI drivers): Android — native 1,074 ms, KMP 1,307, RN 2,186, Flutter 3,075; iOS — RN 1,303, KMP 1,589, native 1,606, Flutter 1,872. RN's iOS "lead" is an artifact of its much shorter scroll driver (77 ms vs ~872 ms native) and "is not evidence of a general React Native advantage."
6. [Research] Render 50 rows (mean ms): iOS — Flutter 34.0, KMP 36.5, RN 44.6, native 49.7; Android — KMP 27.4, native 45.3, Flutter 95.4, RN 102.3. Scroll timings are not comparable across frameworks (different drivers/animation rules); frame pacing, jank, and perceived smoothness were not measured.
7. [Research] Footprint (SLOC, authored mobile source incl. benchmark/telemetry code): combined native 9,105 (iOS 4,522 + Android 4,583); Flutter 5,466 (−40.0%); React Native 4,209 (−53.8%); KMP 4,195 (−53.9%). KMP shared Kotlin is 38.7% of unique KMP source (~55.8% of two-target source incidence) because it keeps two native UIs.
8. [Research] File organization/dependencies: median SLOC per file — native iOS 43, RN 54, native Android 98, Flutter 130, KMP 157.5; largest file — Flutter 1,989 SLOC, native Android 1,127, KMP 1,116, RN 498, iOS 363. Direct production dependencies — native iOS 2, Flutter 10 pub packages, RN 10 npm packages, native Android 19, KMP 19.
9. [Research] Known parity deviations: RN times Expo Image's `loadAsync` (native-backed reference) rather than an explicit codec decode; upload/multipart handling, list virtualization and scroll animation differ; runtime-origin markers are not cold starts; raw nested telemetry kept only for the final run.
10. [Research] Threats to validity stated by author: only time behavior measured — no CPU, memory, energy, package size, or startup; runs are sequential, not randomized/interleaved, and autocorrelated (treating rows as independent overstates precision); one app and one implementation per approach; implementation expertise and library choices confound framework effects; results "may not generalize to games, real-time collaboration, media-intensive applications, offline-first systems, or background-processing workloads."
11. [Research] Author's conclusion: no universally superior technology; choice depends on quality attribute, workload, platform, and measurement boundary; KMP is a "distinct compromise" (native UIs + shared services); teams wanting maximum UI sharing may accept different runtime characteristics from Flutter or RN.
12. [Research] Disclosure: the author acknowledges using generative AI tools (Connected Papers, NotebookLM, Perplexity AI, ChatGPT) for refining, rewriting, and organizing the manuscript.
13. [Inferred] For a media recommender, the measured gaps are in hundreds of milliseconds summed over seven network/storage operations on a non-media workload; the paper explicitly excludes media-heavy generalization, measures no video playback, and its Flutter/RN numbers are tied to specific packages (http/sqflite; Expo SQLite/Expo Image). It is weak evidence for ruling out Flutter or RN for this project; it mainly confirms that shared-UI frameworks cut authored code roughly 40–54% versus two native apps.
14. [Inferred] KMP's code saving comes with two native UIs (SwiftUI shell needs iOS-side work), which for a no-Mac developer means more Apple-toolchain code to write and verify than Flutter or RN.

## Limitations or bias
- Preprint, single author, single app, single implementation per framework; no peer review indicated.
- Descriptive statistics only; sequential, autocorrelated runs; no CPU/memory/energy/startup/package-size data.
- Benchmark and telemetry code included in SLOC counts; KMP variant uses native UIs (not Compose Multiplatform shared UI), so it is not representative of all KMP designs.
- Says nothing about learning curve, AI-assisted development, build/signing, or Mac requirements.
