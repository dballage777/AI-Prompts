## Learned points
1. [Documented] Shopify switched to React Native (RN) for three reasons: "Write it once", "Talent portability" across iOS, Android and Web, and "Ship more value" instead of chasing feature parity. Over five years it migrated all its apps to RN, and each team chose when and how to migrate its own app.
2. [Documented] Shopify reports these results: a "step change in productivity", feature parity between iOS and Android "has become a non-issue", "<500ms screen loads" (P75 in the Shopify app) and ">99.9% crash-free sessions".
3. [Documented] On performance: "native doesn't automatically mean fast, and React Native doesn't automatically mean slow". Fast RN apps still need good patterns. Before committing, Shopify did extensive prototyping.
4. [Documented] Developer experience: hot reloading was "a total game changer". In Shopify's large native codebases, even trivial changes took "several minutes" to compile and run. TypeScript makes it easy to move between React web and RN.
5. [Documented] Native expertise is still essential. You need it to drop to the platform layer, write bindings, handle build, release and distribution, tune performance across devices, and manage RN version updates and new iOS and Android releases. Shopify trained its native developers with a self-serve RN course and office hours, and added web developers to its mobile teams.
6. [Documented] "100% React Native should be an anti-goal." Shopify still uses native for device-hardware features (2D/3D scanning, on-device AI models), memory-limited surfaces (home and lock screen widgets, Apple Watch, App Intents, Siri Shortcuts) and long-running background jobs (for example, POS offline sync).
7. [Documented] Shopify lists these pain points: debugging "is flakey" and VS Code setup takes work (Meta rewrote the debugger stack); each RN version upgrade "takes a significant amount of work and often requires restructuring the code base" (a small rotating group handles upgrades); and RN needs more third-party libraries than native, which brings upkeep and supply-chain risk (handled with Dependabot and automated code scanning).
8. [Documented] Governance and ecosystem: Shopify calls Meta "great stewards", serves as co-release captain for RN releases, sponsors React Native Skia and Reanimated, publishes FlashList, Restyle and Tophat, and restarted the React Native Working Group in 2025. Microsoft, Amazon, Tesla, SpaceX and Coinbase are named as RN users.
9. [Documented] The New Architecture migration covered Shopify Mobile and Point of Sale (hundreds of screens, 40+ native modules in the Shopify app). Weekly releases continued throughout. The approach was to change the minimum code needed, keep both architectures working during development (builds for both on every PR using Tophat, feature flags for incompatible third-party dependencies) and match performance and stability before shipping.
10. [Documented] Shopify migrated no modules to TurboModules during the move, because "they are not mandatory (yet)". It upgraded to the latest RN version first because "The majority of bugs we encountered were fixed with version upgrades." It also patched or removed unmaintained libraries.
11. [Documented] Common migration problems: state batching broke components that relied on intermediate states; blank screens "almost always" pointed to a misbehaving TurboModule or UIManager-touching module; native UIManager view manipulation caused tap and WebView problems (Shopify fixed this by moving WebView lifecycle fully native); view flattening nulled refs and hid views from Appium (fixed with `collapsable={false}` and a Babel plugin); main-thread legacy module setup caused iOS launch deadlocks (`requiresMainQueueSetup` false); and Reanimated frame drops at scale, which Software Mansion patched.
12. [Documented] Store rollout differences that matter for any RN or native app: Google Play lets you set rollout percentages and halt them. The App Store "uses a pre-determined gradual rollout schedule", users can still update manually when a rollout is paused, and approval "can take up to 24 hours, making hotfixes slower and riskier". Shopify's rollout went Android 8%/iOS 0%, then 30%/1%, then 100%/100%.
13. [Documented] Gains after the migration: app launch was about 10% faster on Android and 3% faster on iOS, measure-before-paint gave smoother screens, and batched state meant fewer re-renders. Costs: up to 20% slower loads on some complex components, crash-free sessions below the 99.95% target for "a couple of weeks", and ANR spikes on both platforms.
14. [Inferred] For a solo developer, Shopify's lessons are a warning about upgrade effort. A large team needed a dedicated rotating group for RN upgrades. A solo app should keep its dependency count low, prefer well-maintained libraries that support the New Architecture (video and IAP libraries especially), and upgrade often rather than skip versions.
15. [Inferred] Being a large company, Shopify's experience only partly fits a solo, no-Mac project. It describes no cloud-build or no-Mac workflow and does not use Expo in these posts, and its native expertise is the thing a solo developer leaning on Claude Code lacks.

## Limitations or bias
- These are self-reports from a large company that is invested in RN (it sponsors and co-captains releases), so they lean positive. The metrics are Shopify's own and were not independently checked.
- The scale (large teams, hundreds of screens, 40+ native modules) is very different from a solo app.
- Neither post discusses Expo, EAS, AI-assisted development or building without a Mac.
- The New Architecture post predates RN 0.82, where the New Architecture became mandatory (see S8).
