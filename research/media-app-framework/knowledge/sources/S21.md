## Learned points
1. [Documented] Builds are configured by a `codemagic.yaml` that must be committed at the repository root; when present it overrides any Workflow Editor configuration. A minimal workflow sets `max_build_duration: 120` and `instance_type: mac_mini_m2`; Android and iOS can be separate workflows in the same file. Flutter version is pinned per workflow (`flutter: stable|beta|master|3.x.y` or `flutter: fvm` reading `.fvmrc`; build fails if the file is missing).
2. [Documented] The build machines list in the sidebar shows macOS images with Xcode 16.0 through 27.3 (Xcode 26.6.x marked "default", 27.3.x "edge"), plus Linux (Ubuntu 24.04) and Windows 2022 machines. So iOS compilation happens on Codemagic's Macs, not the developer's machine.
3. [Documented] "With automatic code signing, Codemagic will create both the certificate and the provisioning profile on your behalf without requiring a Mac." Automatic signing works through an App Store Connect API key (Issuer ID, Key ID, .p8 file, downloadable only once; App Manager access recommended). Signing iOS apps "requires Apple Developer Program membership."
4. [Documented] In the codemagic.yaml flow, Code signing identities (team settings) can Upload a .p12, Generate a new Apple Development/Distribution certificate via the API key (downloadable once, with password provided), or Fetch a certificate previously generated by Codemagic. Certificates not generated by Codemagic cannot be fetched because Codemagic lacks their private key. Apple limits Apple Distribution certificates to 3.
5. [Documented] Provisioning profiles can be uploaded (.mobileprovision) or fetched from the Apple Developer Portal by the API key; the yaml then references them via `ios_signing: distribution_type: app_store` + `bundle_identifier` and the script `xcode-project use-profiles`. Changing app ID capabilities or certificates invalidates a profile, which must be regenerated and re-uploaded.
6. [Documented] The manual path still assumes a Mac: "If you don't have an existing certificate, you will have to first generate the signing certificate using Xcode", then export a .p12 from Keychain Access. Several instructions also use macOS-only `pbcopy`. A no-Mac developer should therefore use the automatic/Generate-certificate route.
7. [Documented] The Flutter iOS build script is `flutter pub get`, `pod install` (for each Podfile), `flutter build ipa --release --export-options-plist=/Users/builder/export_options.plist`, with artifacts `build/ios/ipa/*.ipa`. Android: `flutter build appbundle --release`; Android keystore is created with `keytool` (works on Linux) and uploaded; the uploaded keystore "cannot be downloaded from Codemagic", so the developer must keep a copy.
8. [Documented] Publishing to App Store Connect uses the API key (`integrations: app_store_connect: <key name>`, `publishing: app_store_connect: auth: integration`) with options `submit_to_testflight`, `beta_groups`, `expire_build_submitted_for_review`, `submit_to_app_store`, `cancel_previous_submissions`, `release_type: SCHEDULED`, `phased_release`. The build must be signed with a distribution certificate. TestFlight internal-only builds use `--custom-export-options='{"testFlightInternalTestingOnly": true}'`, skipping beta review.
9. [Documented] An app record must already exist in App Store Connect, and "It is recommended to upload the very first version of the app manually." If the first version is not uploaded manually, screenshots, privacy policy URL and category must be filled in App Store Connect (web) after the build. The docs do not say a Mac is required for this step.
10. [Documented] Simulator builds: Apple requires an unsigned `.app` for simulators; Flutter uses `flutter build ios --simulator` (artifact `build/ios/iphonesimulator/Runner.app`); `flutter build ios --debug --no-codesign` gives an unsigned debug .app.
11. [Documented] App Preview is Codemagic's "iOS simulator and Android emulator running in your browser … regardless of the operating system you are using". It is "available for teams only"; Pay-as-you-go teams get 100 free trial minutes, then $0.095/min. Sessions last at most 20 minutes, one concurrent session by default. The pricing comparison table lists "iOS & Android app preview" as "$0.095 / minute", "Unlimited minutes for $3,000 / year" and "Custom". The row has only three values for four plan columns, so which plan each value applies to is ambiguous in the text extract (probably PAYG / Fixed / Enterprise).
12. [Documented] Remote access: per build you can enable SSH or VNC to the build machine; VNC lets you use preinstalled Xcode and iOS simulators "without owning a Mac yourself". Credentials are generated per build and revoked when the build ends. It must be enabled manually in the UI for each build.
13. [Documented] Pricing (codemagic.io/pricing): Free individual plan has 1 user, unlimited apps, 500 free macOS M2 minutes/month refilled, max 1 parallel build, community support, 30-day build history, 120-min build limit. Pay as you go has $0 base, Mac mini M2 $0.095/min, M4 $0.114/min, Linux/Windows $0.045/min, extra concurrency $49/month. Fixed price is $3,990 / $5,400 / $9,000 per year (M2/M4/M4 Max, 3 concurrent builds). Enterprise starts at $24,000/year. Free accounts are offered to teachers, students and non-profits. Prices exclude tax.
14. [Documented] The pricing page also lists Codemagic Patch, an OTA update service for React Native and Capacitor (works with Expo bare and managed). It is free under 100K MAU, then $99/month per additional 100K MAU. It is not for Flutter (Flutter code push in the docs sidebar is "Code Push with Shorebird").
15. [Documented] The docs sidebar has a "Codemagic Knowledge for AI Agents" page (not read).
16. [Inferred] For this solo, no-Mac, Claude Code project: Codemagic documents an end-to-end path for signing, building and submitting a Flutter iOS app with no Mac. It needs a paid Apple Developer membership, an App Store Connect API key, automatic signing or Codemagic-generated certificates, and App Store Connect web for the app record and first-version metadata. A rough cost check: about 500 free M2 minutes/month at maybe 10–20 min per iOS build gives a few dozen iOS builds/month on the Free plan (build length is my estimate, not documented). Interactive debugging on iOS is limited to time-boxed VNC sessions on build machines or paid browser App Preview (teams only). App Preview is not on the single-user Free plan as worded; whether a one-person team on Pay as you go qualifies is not stated.

## Limitations or bias
- Vendor documentation and pricing; Codemagic sells exactly the no-Mac workflow it describes.
- "Upload the very first version manually" does not say how to do that without a Mac; I did not verify whether the first upload can also be done by Codemagic's publishing step (the docs imply it can, with manual metadata afterwards).
- Prices can change; the pricing page has no date.
- I did not read the Codemagic AI-agent knowledge page, the "Alternative code signing methods" page or the Workflow Editor Flutter publishing pages.
