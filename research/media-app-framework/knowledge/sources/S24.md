## Learned points
1. [Research] Preprint. Task design: 50 feature-implementation tasks taken from real product requirements at XiaoHongShu (300M+ MAU), on a production iOS codebase of about 500K lines of mixed Swift/Objective-C (repo about 5 GB). Inputs are a PRD (450 words on average). 70% of tasks include a Figma design and 92% include reference images. The output is a unified diff. There are 449 human-verified tests, 9.1 per task on average, and 4.2 files modified per task on average.
2. [Research] Evaluation does not compile or run the app. Pytest suites inspect the diff text ("diff-based intent tests") using flexible pattern matching. The authors chose this to avoid build overhead and "simulator/device nondeterminism". Runtime and UI correctness are therefore not measured. They say this is a limitation and list simulator-based evaluation as future work.
3. [Research] 22 agent-model configurations were run across Cursor (v2.3), Codex CLI (v0.77.0), Claude Code CLI (v2.1.37) and OpenCode (v1.1.44). Models: Claude Opus 4.5, Sonnet 4.5, Haiku, GLM 4.6/4.7, GPT 5/5.1/5.2 and Gemini 3 Pro. All runs were on macOS 14.x. Figma designs were accessed through the official Figma MCP; GLM used a GLM Vision MCP.
4. [Research] Headline result: the best task success rate is 12% (Cursor + Opus 4.5, Cursor + Sonnet 4.5, Codex + GLM-4.6). The best test pass rate is 28.1% (Cursor + Opus 4.5; Codex + Sonnet 4.5). Agents often make partial progress without completing the task.
5. [Research] Claude Code results (Task success / Test pass / $ per task / minutes): GLM-4.6 10.0% / 26.7% / $1.30 / 11.7. Sonnet 4.5 10.0% / 24.7% / $2.00 / 13.3. Opus 4.5 8.0% / 21.8% / $4.00 / 15.0. Haiku 8.0% / 18.3% / $0.50 / 8.3. In three repeated runs, Claude Code + Opus 4.5 scored 6%, 8% and 6% (mean 6.7%, σ 1.15%); Codex + Opus 4.5 was stable at 4%.
6. [Research] The agent scaffold matters as much as the model. Opus 4.5 scored 12% on Cursor, 8% on Claude Code, 4% on Codex and 2% on OpenCode (6× gap). Sonnet 4.5 scored 12 / 10 / 10 / 4. Commercial agents beat open-source OpenCode, whose best was 8% with GLM-4.6. OpenCode + Opus 4.5 was the most expensive configuration ($9.33/task) and scored 2%.
7. [Research] Complexity effect: 18% success for tasks touching 1–2 files vs 2% for 7+ files. Patches under 50 lines succeed 20% of the time vs 3% for patches over 200 lines. By difficulty, Easy tasks pass 18.5% and Hard tasks 5.8%. Agents do better on Data Management tasks and struggle with "Gesture & Interaction and Media tasks, which require complex multi-modal reasoning."
8. [Research] Failure modes (best agents): missing feature flags 54%, missing data models 22%, missing files 11–15%, missing UI components 11–15%, missing required methods 9%, incomplete multi-file implementation 4–7% (concentrated in features touching 5+ files). The discussion also cites a "25% failure rate due to requirement misunderstanding" and under-use of the visual designs.
9. [Research] Prompt ablation: 12 variants, Claude Code + GLM 4.6 only. "Defensive Programming" raised test pass rate from 19.3% (baseline) to 26.7% (+7.4 points) at the same 10% task success. Quality Focused, Example Driven and Chain of Thought also scored 10% task success. Detailed Role, Structured Checklist, Context Rich and Comprehensive fell to 4%, Test Driven to 6%, and Figma Emphasis and Explicit Instructions to 8%. Conclusion: "prompts focusing on code quality outperform those emphasizing workflow"; overly detailed checklists hurt.
10. [Research] The winning prompt (P10) asks the agent to handle "Empty data, nil values, invalid formats; Very long/short text, different screen sizes; Slow network, timeouts, concurrent operations; First-time user, offline mode, low memory", and says "Don't just implement the happy path." The worst prompt (P12, "Comprehensive") was an 8-step process checklist. The authors say it made the model focus "on process rather than actual implementation".
11. [Research] Qualitative agent differences: Cursor is best at exploratory search but "may not modify all" files it finds. Claude Code is "More conservative, produces well-formed patches for files it chooses to modify". Codex has strong generation but weaker navigation. OpenCode "often gets stuck in endless file reading loops".
12. [Research] Practitioner advice from the authors: treat agents as "copilots" requiring human oversight. Structure PRDs to list affected files and reference similar code patterns. Start with isolated, well-scoped modules. Human review is critical. Use agent output as a first draft. Success predictors are 1–3-file changes, explicit architectural guidance and existing patterns to copy. Failure predictors are logic spread across layers, implicit requirements ("everywhere"), and coupled UI and logic changes.
13. [Research] Stated limitations: a single iOS codebase only, so no Android, Flutter or React Native. No payment integration among the task types. Diff-text grading. Prompt study on one configuration. Costs at experiment-time pricing. The dataset is private, with hosted evaluation at swebenchmobile.com.
14. [Inferred] For this project: the 8–12% figures apply to large legacy native iOS codebases and production practices (feature flags) in Swift/ObjC. They do not apply directly to a small greenfield Flutter/RN app. The transferable lessons are: keep agent tasks to 1–3 files; give explicit file and pattern guidance (e.g., in CLAUDE.md); prefer a short defensive, edge-case-focused instruction over long process checklists; and require human or test verification. The study never compiles or runs code, so it says nothing about how well agents handle Xcode builds or signing.

## Limitations or bias
- This is a preprint (v1), not peer-reviewed. Co-authors from Xiaohongshu own the codebase.
- n = 50 tasks, so a one-task difference is 2 points. Most configurations were run once. Differences of 2–4 points between agents are within noise, per their own variance figure (±1 task).
- Grading by diff pattern matching may reward or penalize style. The "missing feature flags" failures reflect company-specific conventions.
- The model versions (Opus 4.5 etc., CLI versions early 2026) are already older than the current agent and model releases.
- There is a small text inconsistency in the paper: the abstract says Defensive prompts "outperform complex ones by 7.4%", but the body says +7.4 points over the baseline.
