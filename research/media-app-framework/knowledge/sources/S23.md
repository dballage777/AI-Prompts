## Learned points
1. [Documented] video_player 2.14.1 is published by publisher flutter.dev (first-party Flutter team). License BSD-3-Clause. Platforms: Android SDK 24+, iOS 13.0+, macOS 10.15+, Web ("Any*"). 3.73k likes, 140/160 pub points, 4.16M downloads. 163 versions in total.
2. [Documented] Backing players: AVPlayer on iOS/macOS (formats vary by iOS version; query `AVURLAsset.audiovisualTypes`) and ExoPlayer on Android. On web, formats and autoplay depend on the browser. `VideoPlayerController.file` throws `UnimplementedError` on web. `VideoPlayerOptions.mixWithOthers` is silently ignored on web.
3. [Documented] Setup: http (non-https) URLs on iOS need `NSAppTransportSecurity` entries in Info.plist. Android network video needs the `INTERNET` permission. macOS needs the `com.apple.security.network.client` entitlement.
4. [Documented] Optional `VideoViewType.platformView` (added in 2.10.0) uses platform views instead of a texture. The readme warns that "on some platforms the use of platform views may have correctness issues in certain circumstances due to limitations of Flutter's platform view system."
5. [Documented] Recent changelog: 2.14.1 fixes late position updates after dispose and needs Flutter 3.41/Dart 3.11. 2.14.0 adds HLS/DASH video-quality selection (`getVideoTracks()`, `selectVideoTrack()`). 2.13.0 adds `preventsDisplaySleepDuringVideoPlayback` (iOS/macOS). 2.12.0 adds `backBufferDurationMs` (Flutter 3.38). 2.11.0 adds audio-track selection. 2.6.0 added HTTP headers for M3U8 on Android. 2.8.0 added macOS.
6. [Documented] Release cadence from the versions tab: 2.14.0 about 3 months ago, 2.13.0/2.12.0 about 4 months ago, 2.11.x 8–9 months ago, 2.10.x 12–17 months ago. Minimum Flutter/Dart SDK is raised often (e.g., 3.27 → 3.29 → 3.38 → 3.41 across 2.10–2.14), so staying current forces Flutter SDK upgrades.
7. [Documented] Score breakdown: it loses 10 points on platform support (no Windows/Linux) and 10 on static analysis. The analysis INFO is "'package:flutter/material.dart' is deprecated and shouldn't be used. Use package:material_ui/material_ui.dart instead. This feature was deprecated after v3.47.0-0.0.pre." It is flagged not WASM-compatible (imports dart:io). It is marked "Swift PM-ready" and "Built-in Kotlin-ready".
8. [Documented] The video_player readme does not mention YouTube. It plays media URLs or files. Its "Usage" section says it "is not complete as of now".
9. [Documented] youtube_player_iframe 6.0.4 (publisher sarbagyastha.com.np, a single-developer domain) has 672 likes, 160 pub points and 295k downloads, on Android, iOS, macOS and web. Banner: "youtube_player_iframe is no longer maintained." It has been "superseded by youtube_player". It is built on webview_flutter, needs no API key, uses youtube-nocookie.com by default, and offers lazy thumbnails, fullscreen handling and live streams. Using it means you "agree to the YouTube API Services Terms of Service."
10. [Documented] youtube_player 4.0.3 is the successor, from the same publisher. It uses the IFrame Player API in a native WebView via Pigeon/JNI/FFI on Android, iOS, macOS, Windows and Linux, and runs in the page on web. It has 160 pub points but only 25 likes and 422 downloads. Per the iframe package, youtube_player_flutter v11+ is also built on it.
11. [Documented] purchases_flutter 11.0.4 is published by publisher revenuecat.com under the MIT license. 926 likes, 140 pub points, 717k downloads. It wraps StoreKit, Google Play Billing and the RevenueCat backend (server-side receipt validation, cross-platform subscription status, webhooks, analytics). Requirements: Xcode 14.0+, Kotlin 2.1.0+, iOS 13.0+ / Android SDK 21+. pub.dev lists Android, iOS, macOS and web platforms; the readme says iOS, macOS and Android.
12. [Inferred] For a trailer-playing recommender: trailers on direct MP4/HLS URLs fit the first-party video_player well (HLS quality selection since 2.14.0). YouTube-hosted trailers need a third-party WebView/IFrame wrapper. That ecosystem is currently mid-migration: the popular package is unmaintained, and its successor is days old with low adoption and a single maintainer. Treat it as a maintenance risk and check YouTube API ToS. RevenueCat's package is vendor-maintained and actively released, which suits subscriptions.

## Limitations or bias
- Registry metrics (likes, points, downloads) measure popularity and static hygiene, not runtime quality. Pub points are automated.
- Dates are relative ("N days ago") and were converted by me.
- I did not read the GitHub issue trackers (github.com HTML is blocked), so open bugs and known playback issues are not covered beyond the readme's own caveats.
- The purchases_flutter changelog/versions tabs and the youtube_player readme in depth were not read.
