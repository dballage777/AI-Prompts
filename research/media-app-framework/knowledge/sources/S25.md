## Learned points
1. [Documented] Compose Multiplatform 1.8.0 (May 2025) declared Compose for iOS Stable and "production-ready". JetBrains claims feature parity with Jetpack Compose "for all popular use cases", type-safe navigation with deep linking, resource management, and VoiceOver/AssistiveTouch/Full Keyboard Access accessibility. "All major APIs are now officially stable, with strong compatibility guarantees and minimal breaking changes expected in the future."
2. [Documented] Native-feel claims: iOS scroll physics, native text selection with RTL, system drag-and-drop, respect for font size and contrast settings, and iOS navigation gestures. 1.8.0 also improved interop with SwiftUI and UIKit, so Compose can be embedded in native screens and native views can be embedded in Compose. The Respawn iOS app is cited as sharing 96% of its code with Android.
3. [Documented] Performance claims (vendor benchmark; the methodology was "to be published soon"): startup "comparable to native apps", scrolling "on par with SwiftUI", and about 9 MB added to iOS app size vs a fully native SwiftUI app. JetBrains' survey says "over 96% of teams using Compose Multiplatform on iOS report no major performance concerns." Named adopters: Markaz, Wrike, Feres and Physics Wallah.
4. [Documented] The ecosystem is catalogued at klibs.io, and Jetpack libraries are "adopting multiplatform capabilities". The Aug 2025 roadmap says JetBrains is working with Google to bring more Jetpack libraries (Navigation 3, Paging 3) to Compose Multiplatform. None of these posts mentions specific video-player or in-app-purchase libraries.
5. [Documented] Tooling history (Feb 2025): JetBrains dropped its standalone Fleet-based KMP IDE ("will no longer be releasing a standalone IDE for KMP"), deprecated KMP in Fleet within three months, and moved to KMP support on the IntelliJ Platform (IntelliJ IDEA and Android Studio). It cites Google's official KMP support on Android and its Junie coding agent as reasons. This is an example of a vendor changing direction on tooling.
6. [Documented] No-Mac limits (Aug 2025 roadmap): the KMP IDE plugin was coming to Windows and Linux. There you can create projects, run preflight checks, use Compose Hot Reload, and run Android, web, desktop and server apps, but "Due to Apple tooling restrictions, Swift support and iOS run configs won't be available." Without a Mac, a developer can't run or debug the iOS target from the IDE.
7. [Documented] Aug 2025 priorities: "Make the iOS target a pleasure to work with". Kotlin/Native build speed "remains a common Kotlin/Native concern". Swift Export is still experimental, with a stable release aimed for 2026. Compose for Web and Kotlin/Wasm were going to Beta. A new native-feeling iOS text input was planned. A compatibility matrix is planned because "Upgrading dependencies shouldn't be a guessing game." klib cross-compilation was being stabilized so libraries can be built "without requiring macOS machines" (this is about library publishing, not app builds).
8. [Documented] Oct 2026 change: starting with IntelliJ IDEA 2026.3 and Android Studio Rabbit 2 | 2026.2.2, Swift language IDE features (editing, highlighting, Swift–Kotlin navigation) are removed from the KMP plugin, with no planned replacement. "Running iOS applications and debugging Kotlin code on iOS will remain fully supported." The stated reason is that most iOS developers on KMP "prefer using Xcode for Swift development".
9. [Documented] Kotlin Toolchain 0.14 (Nov 2026) adds `kotlin publish testflight`, a guided flow to publish a new iOS app to TestFlight and then automate updates. It uses an App Store Connect access token (Apple Developer Program membership required) and does not store the private key or ask for Apple ID credentials. "You can also still access an Xcode project" for manual signing and advanced options. The post does not say whether this command runs on Linux or needs macOS/Xcode.
10. [Documented] Agentic support in Toolchain 0.14: the CLI wizard generates an MCP server configuration and an AGENTS.md. Kotlin Toolchain skills are installable with `npx skills add kotlin/kotlin-agent-skills`. JetBrains says "Our AI evals show that using these skills helps to reduce the token consumption". The Toolchain is described as a CLI for building, running, testing and publishing Android, iOS, desktop and web apps "whether you're developing with AI agents or writing code yourself". Related-post titles also mention Toolchain 0.13 being "recommend[ed] … for most new KMP projects" and a "Kotlin Benchmark 2.0" of AI coding agents (not read).
11. [Documented] Compose Hot Reload was "already available" in May 2025, and a new KMP plugin for IntelliJ IDEA and Android Studio was announced with Compose Previews in common code.
12. [Inferred] For a solo developer with no Mac using Claude Code on Linux: KMP/CMP's shared UI and logic can be written and Android-tested on Linux. The iOS target still depends on Apple tooling. JetBrains says iOS run configs are unavailable on Linux/Windows, Kotlin/Native compiles for iOS in practice on macOS (not stated explicitly here), and the 2026 posts still route iOS-specific work through Xcode. A cloud Mac CI (e.g., Codemagic, S21) would be needed for iOS builds and signing. The tooling has changed direction often (Fleet IDE dropped in 2025, Swift IDE support dropped in 2026, new Kotlin Toolchain CLI), which is a maintenance-churn signal. The new agent skills, MCP config and AGENTS.md generation are a positive for agent-driven work.

## Limitations or bias
- Every page is vendor marketing or a roadmap from JetBrains. The performance numbers come from a JetBrains benchmark whose methodology had not been published at the time, and the "96%" figure is from JetBrains' own survey.
- The roadmap describes intentions (Aug 2025, a 6–12 month horizon). I did not check which items actually shipped, apart from the 2026 posts read.
- None of the posts explicitly says "a Mac with Xcode is required to build for iOS". The Mac dependency is inferred from the Linux/Windows plugin limits and the Xcode references.
