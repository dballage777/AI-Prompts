## Learned points
1. [Reported] The About page says the survey gathered "3501 responses in total", with every question optional and respondents not filtered. Per-question counts are much lower: about 1,450–1,490 for background questions (for example 1,488 = 98% of question respondents on target platforms) and about 900–940 for architecture and tooling. Results are self-selected, promoted on social media and the This Week in React newsletter.
2. [Reported] Build and publish, as "used it" share: EAS Build 68.2% (n=929), GitHub Actions 61.9%, manually with Xcode 60.3%, manually with Android Studio 55.9%, EAS Submit 54%, Fastlane 47.1%, EAS Workflows 25.3% (59.9% have heard of it), Bitrise 18.7%. Expo's commentator says EAS Workflows nearly tripled, from 9% to 25%.
3. [Reported] Build and publish pain points (free text, only 52 respondents): CI/CD and workflows 9, configuration 8, environment management 8, stores 8, build time 8, failures 5, signing 4, submitting 4.
4. [Reported] New Architecture: 733 of 932 have migrated (about 79%), 137 plan to, 55 have not, and 7 don't plan to. The intro says "New architecture is at 80% adoption now". Expo is credited with making the switch "seamless".
5. [Reported] Frameworks used in the last year: Expo CLI 86.18% (798 of 926), RN Community CLI 47.73%, Rock 2.59%. Starter templates: create-expo-app 82.15%. Tools used: Expo CLI 75.99%, EAS CLI 65.35%, Expo DevClient 64.67%, Expo Go 53.34%, config plugins 43.83%.
6. [Reported] Upgrade strategy (n=929): "Upgrade in parallel with Expo SDK releases" 446 (about 48%), upgrade occasionally 208, stay on latest 141, don't upgrade until forced 86. Main RN version: 0.81 261, 0.83 200, 0.82 179, 0.79 145 (n=940).
7. [Reported] OTA solutions (n=582): EAS Update 80.24%, CodePush 20.27%, self-hosted 11.51%, Bitrise CodePush 2.23%, Codemagic CodePush 1.89%. APIs used (n=848): New Architecture 74.41%, Hermes 60.14%, Expo Modules API 52.95%, OTA updates 42.1%, Fabric 37.5%, Nitro Modules 34.67%.
8. [Reported] AI code generation (n=930): the most common answers were 25% AI (228) and 12.5% AI (197). 155 said 50%, 90 said 75%, 45 said 87.5% and 10 said 100%. Only 33 said 0%. The page shows a median or mean marker of "38%". The conclusion notes "an even larger percentage of code written with AI tools".
9. [Reported] TypeScript dominates: 676 of 928 write 100% TypeScript, and 141 more write 90% TS. Package managers: npm 58.87%, Yarn berry 36.26%, bun 32.79%, pnpm 32.58%.
10. [Reported] Developer background: React developer 875 of 1,467, other frontend 611, backend 516, started with RN 230, Android 186, iOS 156. Professional use 1,300 of 1,479. Team size: solo developer 493 of 1,478 (about 33%, the largest group), 2 people 265, 3–5 people 424.
11. [Reported] Desktop OS for RN development (n=1,470): macOS 1,261, Windows 267, Linux 148. Daily preview platforms (n=1,477): iOS Simulator 1,093, Android physical device 903, iOS physical device 863, Android Emulator 856, web browser 241.
12. [Reported] Target platforms (n=1,488): Android 1,430, iOS 1,380, web 350, macOS 61, Android TV 46, tvOS 45. Industry sectors include Entertainment 157 and Video 58. Size of the top app's user base ranges widely, from "only me" (174) to 1M+ (169).
13. [Reported] Opinions (n about 900): "RN moving in the right direction" got 775 agree or strongly agree (about 86% of 902; the conclusion says 88%), mean 4.2 of 5. "Building RN apps is overly complex" averaged 2.6, with 478 disagreeing and 158 agreeing. "Ecosystem changing too fast" averaged 3.0, with 281 agreeing and 306 disagreeing.
14. [Reported] Pain points (free text, n=260): ecosystem and dependencies 82, version changes 38, building 36, upgrades and maintenance 35, Android experience 34, Expo 30, performance 29, debugging 28. Missing features (n=194): native features 43, better UI solutions 32, performance 29, missing libraries 26. Advantages (n=208): ease of learning 94, cross-platform 80, ecosystem and community 57, native performance and feel 52.
15. [Reported] Libraries (only the top 5 render): Reanimated used by 93.2% (n=1,028), inline styling 91.2%, the StyleSheet API 90.3%, react-navigation 79%, the Animated API 72.9%. Video and payment libraries were not visible in the static page.
16. [Inferred] For this project: Expo and EAS is the community default, with about 86% using Expo CLI, 68% EAS Build, 80% of OTA users on EAS Update and about 48% upgrading in step with Expo SDKs. A third of respondents are solo developers, so a solo Expo setup is mainstream. But 86% develop on macOS and only 148 of 1,470 on Linux, and the iOS Simulator is the most-used daily preview. A Linux-only, Mac-free workflow is therefore unusual, and community advice assumes a Mac by default.

## Limitations or bias
- The survey is run by Software Mansion, a major RN library vendor. Commentary is written by Expo, Software Mansion and Amazon staff, who have a stake in RN and Expo looking good.
- The sample is self-selected and RN-only, so it can't compare frameworks and it favors engaged RN users. Free-text pain-point questions had small samples (52–260).
- "3501 responses" doesn't match per-question counts (at most about 1,490). It may count partial submissions. The page doesn't explain this.
- The libraries page only partly rendered without JavaScript, so most library data, including any video library numbers, was not captured.

## Summary-only items
- Year-over-year trend charts (for example EAS Workflows going from 9% to 25%) were read only through commentary text, not chart data.

## Best used for
- Adoption numbers for Expo, EAS Build, EAS Update and the New Architecture, the share of solo developers, the use of AI-generated code, and evidence that RN development assumes a Mac (86% of respondents use macOS).
