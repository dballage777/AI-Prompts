## Learned points
1. [Documented] Base URL `https://api.myanimelist.net/v2`. Endpoints include GET /anime (search `q`, limit up to 100), /anime/{anime_id}, /anime/ranking (ranking_type all|airing|upcoming|tv|ova|movie|special|bypopularity|favorite, limit up to 500), /anime/season/{year}/{season}, /anime/suggestions (user token only), and the matching /manga endpoints, plus user list endpoints.
2. [Documented] Every call needs authentication. Public reads accept the header `X-MAL-CLIENT-ID: <client id>` ("When user login is not required"). User features need an OAuth2 Bearer token (authorization URL https://myanimelist.net/v1/oauth2/authorize, scope `write:users`). There is no anonymous access.
3. [Documented, live test] Without a key the API refuses requests. `curl -s 'https://api.myanimelist.net/v2/anime/52991?fields=media_type,status'` returned HTTP 403 with `{"message":"","error":"forbidden"}`. A Claude Code session needs a registered client ID to use MAL directly.
4. [Documented] The API returns few fields by default. You must ask for them with `fields=` (nested syntax is allowed, e.g. `my_list_status{priority,comments}`). The documented anime detail field list includes alternative_titles, start_date, end_date, synopsis, mean, rank, popularity, num_list_users, num_scoring_users, nsfw, media_type, status, genres, num_episodes, start_season, broadcast, source, average_episode_duration, rating, related_anime, related_manga, recommendations, studios, statistics.
5. [Documented] `media_type` (anime) values: unknown, tv, ova, movie, special, ona, music. Manga `media_type` values: unknown, manga, novel, one_shot, doujinshi, manhwa, manhua, oel. Anime `status` values: finished_airing, currently_airing, not_yet_aired.
6. [Documented] `num_episodes`: "The total number of episodes of this series. If unknown, it is 0." A value of 0 means unknown or still airing, not zero episodes. `start_season` = {year, season ∈ winter|spring|summer|fall}. The seasons map to months as winter Jan–Mar, spring Apr–Jun, summer Jul–Sep, fall Oct–Dec. `average_episode_duration` is in seconds. Dates may be partial ("2017-10" or "2017").
7. [Documented] `source` values: other, original, manga, 4_koma_manga, web_manga, digital_manga, novel, light_novel, visual_novel, game, card_game, book, picture_book, radio, music. These are more detailed than AniList's v1 source values.
8. [Documented] `rating` (an age rating MAL assigns, not an official one): g = "G - All Ages", pg = "PG - Children", pg_13 = "Teens 13 and Older", r = "R - 17+ (violence & profanity)", r+ = "R+ - Profanity & Mild Nudity", rx = "Rx - Hentai".
9. [Documented] `nsfw` is a separate field: white = "safe for work", gray = "may be not safe for work", black = "not safe for work". The query parameter `nsfw=true|false` controls whether some list endpoints return NSFW entries ("By default, some APIs don’t return nsfw content").
10. [Documented] `related_anime` / `related_manga` edges hold `node`, `relation_type`, and `relation_type_formatted`. `relation_type` values: sequel, prequel, alternative_setting, alternative_version, side_story, parent_story, summary, full_story. There is no adaptation value inside related_anime; cross-medium links go in related_manga.
11. [Documented] `mean` is left out "when the number of user scores is small". In the sample response, `genres` includes demographic labels such as {id 27, "Shounen"} next to Comedy and Sports. MAL mixes demographics into genres, while AniList puts them in tags.
12. [Documented] `alternative_titles` = {synonyms[], en, ja} ("\"synonyms\" or ISO 639-1"). The reference documents no rate limit; 403 is listed as "DoS detected etc."
13. [Documented] Licence: the agreement grants a "limited, revocable, non-exclusive" licence. Non-commercial apps (personal, educational, open source, free) are allowed. Commercial apps need written authorization. Section 2(i) bans scraping: "will only obtain MyAnimeList Content directly through the API". MyAnimeList reserves the right to limit usage, start charging, or terminate access, and you must delete everything on termination.
14. [Documented] Other licence terms: Company Marks may be used only to attribute MyAnimeList as the source (e.g. "authorized by MyAnimeList"). You may not store user personal information or user-generated content (e.g. forum posts) on the server side; client-side storage is allowed only for as long as is "reasonably necessary". Clause 2(vii) forbids combining "the API with any software, applications, technology, services, or materials not expressly authorized by Company in writing". Read literally, this is very broad.
15. [Inferred] For a personal recommender, MAL works as a secondary check once the user has a client ID. AniList's `idMal` (see S2) or the Fribb mappings (see S22) give the MAL ID without calling MAL. Use `rating` together with `nsfw` for content screening. Treat `num_episodes: 0` as unknown.

## Limitations or bias
- The API is still labelled beta, and its sample URLs point to an old CDN (myanimelist.cdn-dena.com). The docs may be stale.
- No rate limits are published. The agreement dates from 2019 and contains broad clauses (e.g. 2(vii)) whose enforcement is unclear.
- Only a no-key 403 test was possible, so no field values were checked live.
- MAL ratings and genres are site-assigned or community-assigned. They are not official ratings from a national rating body.

## Summary-only items
- None (the OAuth flow details and the manga-specific status enum were not studied in depth).

## Best used for
- A second source for anime type, episodes, season, source and relation data. The MAL age `rating` (G–Rx) and the `nsfw` white/gray/black field are useful content-screening signals. MAL needs a client ID, so it is not key-free.
