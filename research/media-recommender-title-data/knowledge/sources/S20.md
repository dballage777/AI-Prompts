## Learned points
1. [Documented] New 2026 per-user rate limits apply to all Wikimedia sites, covering both the Action API and REST APIs, and are enforced per minute. The goal is to cut unauthenticated automated traffic ("about 33% at the end of 2025") and heavy commercial load.
2. [Documented] Limits (requests/minute): Unidentified (IP only) **10**; unauthenticated web browser 200; **"User-Agent only" (unauthenticated bot with a compliant User-Agent) 200**; third-party MediaWiki wikis 200; authenticated new or low-edit users 200; established editors 2000. Exempt: extended global rights, bot-flagged accounts, WMCS server-side, and WMF-granted known clients (still subject to operational limits and the Robot policy).
3. [Inferred] A Claude Code session using curl with a descriptive User-Agent falls in the 200 req/min tier. Without one (or with a generic UA) it drops to 10 req/min or gets a 403. Always set the UA.
4. [Documented] Best practices: a meaningful User-Agent with contact info (example `CoolBot/0.0 (https://example.org/coolbot/; coolbot@example.org) generic-library/0.0`); 3 or fewer concurrent requests; honour `Retry-After` on 429. If no header is given, "wait at least five seconds, or implement exponential back-off". A 503 means backend overload.
5. [Documented] User-Agent policy format: `<client name>/<version> (<contact information>) <library/framework name>/<version>`. Contact can be an email, website, or `(<project>; User:<name>)`. Include "bot" in the UA if automated. Do not copy a browser's UA ("will be assumed malicious"). Do not use generic agents like "curl", "lwp", or "Python-urllib". Browser JS can use the `Api-User-Agent` header instead.
6. [Documented] Enforcement: "if you don't supply a User-Agent header, or you supply an empty or generic one, your request will fail with an HTTP 403 error". The policy also says that since 2015 enforcement is not automatic for all requests and "may be enforced in specific cases as needed". The policy page states both.
7. [Documented] Action API etiquette: "There is no hard speed limit on read requests". Make requests in series, not in parallel. Batch titles with `|` (e.g. `titles=PageA|PageB|PageC`). Use generators, `Accept-Encoding: gzip`, and `maxlag` for non-interactive tasks. Prefer GET over POST for reads (POST is not cached). Cache data you will reuse. Use JSON. Bulk downloads should use dumps or data services, not the API.
8. [Documented, live test] Page summary via REST: `curl -s -A 'MediaRecResearchBot/0.1 (research run) curl' "https://en.wikipedia.org/api/rest_v1/page/summary/Breaking_Bad"` returned HTTP 200 JSON (profile `https://www.mediawiki.org/wiki/Specs/Summary/1.5.0`). Fields: `type` "standard", `title`, `description` "American crime drama TV series" (`description_source` "local"), **`wikibase_item` "Q1079"**, `timestamp` 2026-11-13T16:35:40Z, `lang`, `extract` (plain-text lead), and `content_urls.desktop.page`. Headers: `cache-control: s-maxage=1209600, max-age=300`, `age: 63022`, so the response can be a cached copy up to about 14 days old at the edge.
9. [Inferred] `wikibase_item` from the summary links a Wikipedia article straight to the Wikidata item used in S10 (Q1079 matches the SPARQL result). That gives a check chain: title → summary → Q-id → IMDb/TMDB/TVmaze/AniList IDs. `type` values other than "standard" (e.g. disambiguation) indicate an ambiguous title. Only "standard" was observed here; other values are not documented in the pages read.
10. [Documented] Users who need high-volume commercial access are pointed to Wikimedia Enterprise APIs ("free access for all users up to certain speed and volume limits"). OAuth 1 and owner-only OAuth 2 tokens count as unauthenticated for rate limiting unless the client returns server cookies.
11. [Inferred] Our test UA had no contact info, which the policy asks for. A real tool should add the user's own project URL or email. Do not invent one.

## Limitations or bias
- Limits are explicitly experimental for 2026 and may change.
- No official REST page-summary documentation was read (the rest_v1 docs URL redirected to a sandbox error). The summary fields come from the live response only.
- Wikipedia text licensing (for reusing `extract`) was not covered by these pages. The Wikimedia "Content reuse" page was seen in navigation but not read.
