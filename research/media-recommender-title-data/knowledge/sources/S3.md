## Learned points
1. [Documented] A key is required. You request one in TMDB account settings and must accept the API terms first. Auth is either the `api_key` query parameter (v3) or the "API Read Access Token" sent as `Authorization: Bearer <token>` (works for v3 and v4, "same level of access"). Live check: unauthenticated `GET https://api.themoviedb.org/3/movie/550` returned HTTP 401.
2. [Documented] There are three ways to find data: `/search` (text, "takes into account all original, translated, alternative names and titles"), `/discover` (filters such as ratings, certifications, release dates), and `/find` (external ID).
3. [Documented] `GET /3/find/{external_id}?external_source=...` takes `imdb_id`, `facebook_id`, `instagram_id`, `tvdb_id`, `tiktok_id`, `twitter_id`, `wikidata_id`, or `youtube_id`. It returns `movie_results`, `tv_results`, `tv_episode_results`, `tv_season_results`, and `person_results`. IMDb and Wikidata IDs are the useful bridges for verification. Each result carries `media_type`, `release_date`, `original_language`, `original_title`, `vote_average`, and `vote_count`.
4. [Documented] Recommended workflow: search, then take the `id`, then call details (`/3/movie/{id}`). Search results include `release_date`, `original_title`, `original_language`, `genre_ids`, `popularity`, `vote_average`, `vote_count`, `adult`, and `video`.
5. [Documented] `append_to_response` (comma-separated) works on movie, TV show, TV season, TV episode, and person details. It bundles sub-requests (e.g. `?append_to_response=videos,images`) into one HTTP call. Sub-requests still honour their own parameters (e.g. language filtering of images).
6. [Documented] Rate limits: the legacy limit of 40 requests per 10 seconds was disabled on December 16, 2019. Current upper limits "sit somewhere in the 40 requests per second range" and "could change at any time". Clients should respect `429`. The FAQ says there is no SLA.
7. [Documented] Daily ID exports are key-free at `https://files.tmdb.org/p/exports/` and are not full data dumps. They are newline-delimited JSON (each line a JSON object, not one JSON file) with ID plus adult/video/popularity. Files: `movie_ids_`, `tv_series_ids_`, `person_ids_`, `collection_ids_`, `tv_network_ids_`, `keyword_ids_`, `production_company_ids_` with `MM_DD_YYYY.json.gz`. Separate `adult_*` files have existed since July 5, 2023. The job starts around 07:00 UTC and finishes by 08:00 UTC. Files are kept 3 months. Authentication "could change at some point".
8. [Documented] Movie certifications live in `GET /3/movie/{movie_id}/release_dates`: per-country `iso_3166_1`, each entry with `certification`, `descriptors`, `iso_639_1`, `note`, `release_date`, and `type`. Release types: 1 Premiere, 2 Theatrical (limited), 3 Theatrical, 4 Digital, 5 Physical, 6 TV. Certifications can be empty (`""`) for premieres and festival entries.
9. [Documented] TV ratings come from `GET /3/tv/{series_id}/content_ratings`: series-level `results[]` of `{iso_3166_1, rating, descriptors}` (example for id 1399: US "TV-MA", DE "16", GB "18", KR "19"). There is no season- or episode-level rating in this endpoint.
10. [Documented] `GET /3/certification/movie/list` and `/3/certification/tv/list` return each country's official codes with `meaning` and `order`. US TV order: NR 0, TV-Y 1, TV-Y7 2, TV-G 3, TV-PG 4, TV-14 5, TV-MA 6. Use `order` to compare strictness within one country, never across countries.
11. [Inferred, from the docs' own examples] Certification strings are not normalised. The release_dates example has AU "R18+" and SG "M18 " (with a trailing space), while the certification list spells AU "R 18+". Trim and normalise before matching against the list.
12. [Documented] Watch providers: `GET /3/movie/{id}/watch/providers` and `/3/tv/{id}/watch/providers` return results per country with a TMDB `link` and `flatrate`/`rent`/`buy`/`ads` arrays (`provider_id`, `provider_name`, `logo_path`, `display_priority`). The data comes from JustWatch. It is "*not* going to return full deep links". "JustWatch Attribution Required", and TMDB "will revoke access" for non-compliance.
13. [Documented] TV episode groups: `GET /3/tv/{series_id}/episode_groups` lists groups (example: "Aired Order", `type` 1, `episode_count` 102, `group_count` 9). Details at `/3/tv/episode_group/{id}`. There are 7 types: 1 Original air date, 2 Absolute, 3 DVD, 4 Digital, 5 Story arc, 6 Production, 7 TV. This is the TMDB mechanism for alternate watch orders, such as absolute numbering for anime.
14. [Documented] Collections: `GET /3/collection/{collection_id}` (with `language`) returns `name`, `overview`, and `parts[]` with each film's `id` and `release_date` (example id 10 "Star Wars Collection").
15. [Inferred, from the docs' example] Collection `parts` are not guaranteed to be in chronological order. The example lists 2015-12-15, then 2019-12-18, then 2017-12-13. Sort by `release_date` yourself for release order. A collection covers films only and is not an in-universe chronology.
16. [Documented] `region` (ISO 3166-1) acts as a presentation filter for release dates and falls back to the primary release date if none exists for that country. `/discover/movie` can combine `region` with `with_release_type` (e.g. `2|3` for theatrical).
17. [Documented] FAQ: the API is free for non-commercial use with attribution. "Your project is considered commercial if the primary purpose is to create revenue". Attribution goes in an About/Credits section with an approved logo. The S5 Terms add AI/chatbot restrictions that matter here.

## Limitations or bias
- TMDB data is community-edited (FAQ: "Any data and/or images you upload you expressly grant us a license to use"), so certifications and episode groups depend on contributors.
- The llms.txt index is incomplete; many reference pages exist that it does not list.
- Example payloads are illustrative and may be stale (e.g. the find-by-id `popularity` value).
- No live authenticated call was made (no key in this session). Field claims rest on the OpenAPI examples.
- The terms (S5) restrict AI/ML use, which may override what the docs make look technically easy.

## Summary-only items
- None. The image, languages, and discover filter pages were not read beyond the region page's mention of `with_release_type`.

## Best used for
- ID bridging (`/find` by IMDb/Wikidata/TVDB ID), per-country certifications, streaming availability (with JustWatch attribution), episode-group watch orders, and film collections.
- Key-free daily ID lists for checking that a TMDB ID exists or is adult.
