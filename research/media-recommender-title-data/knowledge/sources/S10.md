## Learned points
1. [Documented] Endpoint: `https://query.wikidata.org/sparql` (alias of `/bigdata/namespace/wdq/sparql`). GET with `?query=` or POST (`query=` body, URL-escaped). Results come as XML by default, or JSON with `format=json` or `Accept: application/sparql-results+json`; TSV and CSV are also available. GET responses are cached; POST responses are not. No key is needed.
2. [Documented] Limits (User Manual): 60-second hard query deadline. Each client (User-Agent + IP) gets 60 s of processing time per 60 s and 30 error queries per minute. Exceeding these gives HTTP 429 (honour `Retry-After`). Clients that ignore 429s can be temporarily banned, and clients that break the User-Agent policy "may be blocked completely". Each IP may run 5 parallel queries. Limits are "subject to change".
3. [Documented] Backend migration: WDQS is moving from Blazegraph to QLever in 2026–2027 with new v2 endpoint URLs. "At minimum, you must migrate to the new SPARQL endpoints." New endpoints open to the community "by the week of November 16th". Original Blazegraph endpoints "may experience service degradation beginning February 2027". Queries that use Blazegraph-specific features (e.g. possibly `SERVICE wikibase:label`, `mwapi`) may need rewriting. v2 has "no committed SLOs (yet)".
4. [Documented] A graph split already exists. The main graph is at `query.wikidata.org/sparql` and scholarly articles are at `query-scholarly.wikidata.org/sparql`. Film and TV items are in the main graph.
5. [Documented] Licence: "All structured data from the main, Property, Lexeme, and EntitySchema namespaces is available under the Creative Commons CC0 License". There is no attribution obligation and no AI restriction, which makes Wikidata the cleanest data to use with an LLM.
6. [Documented, live test] Query (GET, `Accept: application/sparql-results+json`, UA `MediaRecResearch/0.1 (research run; personal non-commercial)`):
   ```
   SELECT ?item ?itemLabel ?tmdbMovie ?tmdbTV ?anilist ?mal ?tvmaze WHERE {
     VALUES ?imdb { "tt0903747" "tt2560140" }
     ?item wdt:P345 ?imdb .
     OPTIONAL { ?item wdt:P4947 ?tmdbMovie } OPTIONAL { ?item wdt:P4983 ?tmdbTV }
     OPTIONAL { ?item wdt:P8729 ?anilist } OPTIONAL { ?item wdt:P4086 ?mal }
     OPTIONAL { ?item wdt:P8600 ?tvmaze }
     SERVICE wikibase:label { bd:serviceParam wikibase:language "en". } }
   ```
   Result (HTTP 200): Q1079 "Breaking Bad" with TMDB TV 1396 and TVmaze 169 (matches S8's live lookup). Q22126305 "Attack on Titan" with TMDB TV 1429, TVmaze 919, and MAL 16498, but no AniList ID on the series item.
7. [Documented, live test] Follow-up query `?s wdt:P179 wd:Q22126305` (P179 = part of the series) with P8729/P4086. AniList/MAL IDs sit on season items: S1 Q47388290 (AniList 16498 / MAL 16498); S2 Q47388300 (20958 / 25777); S3 Q60518750 (two AniList: 99147, 104578; two MAL: 35760, 38524); "The Final Season" Q100332172 (AniList 110277; MAL 40028, 48583, 51535).
8. [Inferred] Granularity mismatch: IMDb, TMDB, and TVmaze model an anime as one series, while AniList and MAL split it by season or cour, often many-to-many. Wikidata exposes this. Multiple OPTIONAL values multiply rows (S3 returned 4 rows from 2×2 IDs), so use `GROUP_CONCAT` or deduplicate. The MAL ID on the series item is only season 1's ID. Do not treat it as the whole series.
9. [Documented] Property IDs used: P345 IMDb ID, P4947 TMDB movie ID, P4983 TMDB TV series ID, P8729 AniList anime ID, P4086 MyAnimeList anime ID, P8600 TV Maze series ID, P179 part of the series. All returned data in the tests, which confirms they resolve.
10. [Documented] The WDQS dataset "does not exactly match the dataset produced by RDF dumps, mainly for performance reasons". There can also be update lag (the User Manual notes self-hosted catch-up lag; the public lag was not stated in the pages read).
11. [Inferred] Use Wikidata for cross-ID mapping and basic facts (P577 publication date, P31 instance of, P136 genre), then confirm against the primary source (TMDB/TVmaze/AniList). Wikidata is crowd-edited and IDs can be missing or wrong.

## Limitations or bias
- Crowd-sourced and incomplete. Coverage of external IDs varies (AniList was missing on the AoT series item).
- Endpoint URLs and query syntax are changing during the QLever migration (November 2026 onward). The v2 URLs were not recorded because they are linked rather than stated on the pages read.
- The Wikidata:Copyright page's main body text was not separately captured; the CC0 statement came from the page's licence line.
