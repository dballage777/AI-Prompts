## Learned points
1. [Documented] Purpose: a dataset "containing anime metadata aggregated by different anime metadata providers" that allows "cross-references between those metadata providers". It was built for the manami app. It covers anime only, with no manga.
2. [Documented] Size as of week 27 of 2026: 41,537 entries ("65% reviewed"). Provider coverage counts: myanimelist.net 30,570; anime-planet.com 26,674; kitsu.app 22,139; anisearch.com 21,105; anilist.co 20,691; anidb.net 14,517; simkl.com 14,494; animecountdown.com 14,494; animenewsnetwork.com 12,619; livechart.me 12,278.
3. [Documented] Where the files live: "After the _2025-25_ update the dataset files will be removed from the repo and moved to releases instead". A **latest** release always has the newest files, and weekly named releases (e.g. **2025-25**) hold each week's files. Raw-file URLs on the main branch therefore no longer serve the data.
4. [Documented] Files: `anime-offline-database-minified.json` (null values omitted), plus a `.zst` Zstandard version and a JSON schema; `anime-offline-database.jsonl` (the first line is metadata, then one anime per line), plus `.zst` and a schema; `dead-entries/*-minified.json` per provider, listing IDs removed upstream.
5. [Documented] Update cadence: weekly. Releases and tags are named year-week (2025-18, 2025-25, 2026-27). The root object has a `lastUpdate` date (YYYY-MM-DD).
6. [Documented] Anime record fields: `sources` (URL[] of provider pages, which act as the cross-ID set), `title`, `type` ∈ {TV, MOVIE, OVA, ONA, SPECIAL, UNKNOWN}, `episodes`, `status` ∈ {FINISHED, ONGOING, UPCOMING, UNKNOWN}, `animeSeason` {season ∈ SPRING|SUMMER|FALL|WINTER|UNDEFINED, year (nullable)}, `picture`, `thumbnail`, `duration` {value seconds, unit SECONDS} (nullable), `score` {arithmeticGeometricMean, arithmeticMean, median} on a 1.0–10.0 range (nullable), `synonyms`, `studios` and `producers` (lower-case), `relatedAnime` (URL[]), and `tags` (lower-case).
7. [Documented] Tags are "A non-curated list of tags and genres". In the Death Note example they include noise such as "tennis", "feet" and "unusual weapons -- to be split and deleted", alongside "shounen" and "weekly shounen jump".
8. [Documented] `relatedAnime` is a flat list of URLs with no relation type, described as anime "somehow related to this anime". It cannot tell a sequel from a side story or recap.
9. [Documented] `score` is computed from all providers' scores, rescaled when needed. It is a cross-site aggregate, not any one site's score.
10. [Documented] Licence: "Open Database License 1.0" (ODbL) for the database, plus "Database Contents License (DbCL) v1.0" for individual contents. ODbL is share-alike with attribution, so derived databases you publish must keep the licence and credit the source.
11. [Inferred] For a Claude Code recommender this is the best key-free offline lookup. Download the latest release once, then check that a title exists, its type, episode count, year, season and status, and get provider IDs from `sources`, all without rate limits. It is a good fit for a local SQLite or JSON index.
12. [Inferred] The README says week 27 of 2026, but the read date is mid-November 2026 (about week 46), so either the README lags the releases or updates paused. Check `lastUpdate` in the downloaded file before relying on it for currently airing shows.
13. [Reported] Fribb/anime-lists (S22) now names `cedya77/anime-offline-database` as its upstream instead of manami-project. That suggests a fork exists and the upstream situation may have changed. This was not checked here.

## Limitations or bias
- Anime only, with no manga. No age or content rating field and no adult flag (adult status may show only through tags). There is no English-title field; `title` is a main title, often romaji, and the rest are in `synonyms`.
- Tags are not curated and relations have no types.
- 35% of entries are unreviewed (automatically merged), so there may be cross-provider merge errors.
- I could not confirm the release dates or the latest tag because the releases page was blocked.

## Best used for
- Offline, key-free checks that an anime exists, with type, year, season, episodes and status, cross-provider ID mapping (MAL, AniList, AniDB, Kitsu, etc.), and the dead-entry lists for spotting removed IDs.
