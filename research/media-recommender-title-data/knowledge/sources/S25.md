## Learned points
1. [Research] RestBench TMDB scenario: 54 commonly used TMDB endpoints, with their OpenAPI Specifications. The test set has 100 human-written instructions (plus 10 dev). Gold solution paths have lengths 1/2/3/4 for 5/66/27/2 instructions, averaging 2.3 calls. Six NLP experts wrote the instructions and two more verified them. The Spotify scenario has 40 APIs and 57 test instructions.
2. [Research] Example: "Who is the director of today's most trending movie?" has the gold path `GET /trending/{media_type}/{time_window}` then `GET /movie/{movie_id}/credits`. Most TMDB questions need a search or list call to get an ID, followed by a detail or credits call.
3. [Research] Architecture: an online coarse-to-fine loop. The Planner writes the next natural-language sub-task. The API Selector reads only the endpoint descriptions and chooses the call(s). The Executor has two parts. The Caller reads the full documentation for only the selected API and builds the parameters, a description, and "output_instructions". The Parser writes Python code from the OAS response schema to pull fields from the JSON, and falls back to the LLM reading the JSON directly if the code fails. The planner can emit "continue" (re-plan the same sub-task) or "end".
4. [Research] Why split the documentation: context limits. Each module reads a different part of the OAS (descriptions, then per-endpoint parameters, then response schema). TMDB JSON responses can be very long; their parser example was 694 lines.
5. [Research] Success rates on TMDB with text-davinci-003, as Success % / Correct-Path %: Offline plan-then-execute 29/33, DEPS 38/43, ReAct 44/57, Reflexion 52/59, RestGPT 75/79. Without the planner (equal to ReAct plus their executor): 44/57. Without the schema parser: 46/53. RestGPT with ChatGPT: 68/65. With Llama2-13B: 0/0 (could not follow the prompt). With Vicuna-13B: 9/15.
6. [Research] Metrics: Correct Path means the gold API sequence appears as a subsequence of the model's calls. Success was judged by humans, because time-dependent answers (for example "trending") cannot have fixed gold answers. ΔSolution Len counts extra calls beyond the gold path; RestGPT averaged +0.55 on TMDB.
7. [Research] Error types: most errors occur in planning. The Planner loses track after several rounds and exits early. The API Selector picks the wrong API or "hallucinate[s] to make up in-path parameters". The Parser sometimes writes wrong extraction code (for example returning an album name instead of a track). ChatGPT tended to keep planning after the task was done.
8. [Research] TMDB failure case: for "a photo belong to the second episode of the first season of the Witcher", the selector made up the path parameter `tv_id` (63926) instead of searching first, and the task failed. Episode-level lookups need the full ID chain: search, then TV ID, then season, then episode.
9. [Research] Success falls as instructions need more calls. At gold length 4, the baselines mostly fail and RestGPT still exceeds 40%. Adding noise TMDB APIs (starting from 10 hand-picked APIs and 15 instructions) hurt the baselines but barely affected RestGPT.
10. [Research] TMDB case traces show the real ID chain: `GET /search/person?query=Sofia Coppola` returns id 1769, then `GET /person/1769/movie_credits` (parsed for director jobs). Likewise `GET /search/person` (DiCaprio 6193), then `/person/6193/movie_credits` (latest: Killers of the Flower Moon, 466420), then `/movie/466420/credits` (Martin Scorsese 1032).
11. [Inferred] For a Claude Code recommender: always resolve names to IDs through a search endpoint before calling detail, credits, or episode endpoints, and never let the model fill a path ID from memory. Keep a small, curated endpoint list. Parse JSON with code (jq or Python) instead of having the model read huge responses. Verify that the task is complete before stopping.
12. [Inferred] "Latest" or "trending" questions depend on the current date and the live API, which is another reason to call the API instead of trusting memory (see S29).

## Limitations or bias
- Uses 2023 models (text-davinci-003, ChatGPT). Current tool-using models are far stronger, so absolute success rates are dated. The error types are still relevant.
- Small test set (100 TMDB instructions) written by NLP researchers, not real users.
- Success was judged by humans, and no inter-annotator agreement is reported in the parts read.
- Says nothing about TMDB API keys, terms, attribution, or rate limits (see the TMDB-docs sources for those).

## Summary-only items
- Figures 3–4 (error breakdown percentages, scaling curves) are images. Only the prose descriptions were available, so no per-module error percentages are recorded.

## Best used for
- Design patterns and failure types for an LLM agent calling the TMDB API (ID chain, made-up path IDs, schema-based parsing, planner early exit).
- Example TMDB endpoint sequences for typical recommender questions.
