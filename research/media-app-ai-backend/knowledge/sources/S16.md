## Learned points
1. [Documented] `expo/fetch` provides "a WinterCG-compliant Fetch API" that "works consistently across web and mobile environments". The `expo` package is listed for Android, iOS, tvOS and Web, and is included in Expo Go.
2. [Documented] Streaming download works through the standard `response.body.getReader()` and a `reader.read()` loop that returns `{done, value}` with `Uint8Array` chunks. The official example requests with `Accept: 'text/event-stream'`.
3. [Documented] In current SDK docs, on Android and iOS, `expo/fetch` "is also installed as the global `fetch`". Plain `fetch(...)` calls therefore use the WinterCG implementation. To keep React Native's built-in fetch as the global, set `EXPO_PUBLIC_USE_RN_FETCH=1`. Named imports `import { fetch } from 'expo/fetch'` work either way.
4. [Documented] Web Streams are available globally on native: `ReadableStream`, `WritableStream`, `TransformStream`. The docs add that "Expo Hosting server runtime also includes support for the standard web streams API."
5. [Documented] `TextEncoder`/`TextDecoder` are available on all platforms. `TextEncoder`, and from SDK 58 / React Native 0.88 also `TextDecoder`, are provided by Hermes. `TextDecoder` supports UTF-8, UTF-16 and legacy single-byte encodings. `TextEncoderStream`/`TextDecoderStream` are also available, so `resp.body.pipeThrough(new TextDecoderStream())` is supported for decoding streamed text.
6. [Documented] A spec-compliant `URL`/`URLSearchParams` replaces React Native's shims on native. The one documented gap: non-ASCII hostnames are not punycoded on Android/iOS. `structuredClone` is available, but without the `transfer` option.
7. [Documented] Release timing: the SDK 52 changelog (Nov 12, 2024) introduced `expo/fetch` as "a drop-in replacement, WinterCG-compliant Fetch API" that "supports download streaming, which is useful for integrating modern AI APIs that require efficient handling of data streams." SDK 52 shipped with React Native 0.76.
8. [Documented] What the changelog announces is download streaming specifically. Neither page read mentions upload (request-body) streaming.
9. [Documented] The pages read list no specific `expo/fetch` limitations (for example about `redirect`, `credentials`, cookies or `AbortController`). The only stated caveats are URL non-ASCII hostnames and `structuredClone` `transfer`.
10. [Inferred] For this app, the client can consume a streamed Claude response relayed by the backend (SSE or chunked text) using `fetch` + `getReader()` + `TextDecoder(Stream)` on iOS and Android with no extra library. It is still sensible to import `fetch` from `expo/fetch` explicitly, so streaming does not silently break if `EXPO_PUBLIC_USE_RN_FETCH=1` is ever set.
11. [Inferred] The client still has to parse SSE framing itself (`event:` / `data:` lines split across chunk boundaries). The docs provide no SSE parser, so buffer partial lines between reads.
12. [Inferred] The "global fetch is expo/fetch" behavior appears in the current (SDK 58) docs. The SDK 52 announcement describes `expo/fetch` as something you import. When the global replacement started was not established from these pages, so check the version you target.
