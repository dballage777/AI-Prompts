## Learned points
1. [Documented] Anthropic base URL through the gateway: `https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}/anthropic`; Messages calls go to `.../anthropic/v1/messages` with the normal `anthropic-version: 2023-06-01` and `Content-Type: application/json` headers.
2. [Documented] Provider key goes in `x-api-key`; the gateway "does not recognize `Authorization: Bearer` as provider credentials" on the Anthropic endpoint. Gateway auth is separate: `cf-aig-authorization: Bearer {CF_AIG_TOKEN}`. Missing required provider credentials returns error 2044.
3. [Documented] Anthropic SDK pattern: set `baseURL` to the gateway URL, put `x-api-key` and `cf-aig-authorization` in `defaultHeaders`, and set `Authorization: null` to strip the SDK's bearer header. With stored keys (BYOK), pass `apiKey: "placeholder"` and set both `x-api-key: null` and `Authorization: null`. Sending a real key in `x-api-key` bypasses stored keys and Unified Billing.
4. [Documented] An OpenAI-compatible route also exists: `https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/v1/chat/completions` with `"model": "anthropic/{model}"`. Cloudflare recommends the REST API at api.cloudflare.com (standard `Authorization` header) for new integrations; the gateway.ai.cloudflare.com endpoints "continue to work".
5. [Documented] Authentication: new gateways require authentication; once turned on it cannot be turned off (API returns HTTP 400 "Authentication cannot be disabled once enabled"). Tokens need the AI Gateway "Run" permission. Requests from a Worker through an AI Gateway binding are pre-authenticated, so no `cf-aig-authorization` header is needed there.
6. [Documented] AI Gateway tokens are account-scoped: Read/Run/Edit cannot be limited to one gateway, and any token with Run can send requests through every gateway in the account, including ones with stored BYOK keys, "consuming those credentials". For isolation, Cloudflare advises separate accounts or a Worker-side binding.
7. [Documented] BYOK stores provider keys in Cloudflare Secrets Store. The gateway must be authenticated. Via API, the secret must be named `{gateway_id}_{provider_slug}_{alias}` (for example `my-gateway_anthropic_default`). The gateway substitutes the stored key only when the provider auth header is absent; a placeholder value in that header causes a provider auth error. Rotation is immediate with no code change; deletion immediately stops dependent requests. Multiple keys per provider are selected with `cf-aig-byok-alias` (default alias `default`), but Unified Billing endpoints only consult the default alias.
8. [Documented] Gateway rate limiting: a count of requests per time period (example: 100 requests per 60 seconds), with a "fixed" or "sliding" technique. Example given: limit 10 per 10 minutes; 10 requests at 12:09 and 10 at 12:11 all pass under fixed windows but fail under sliding. Exceeding returns HTTP 429. API fields: `rate_limiting_interval`, `rate_limiting_limit`, `rate_limiting_technique`. It "will be uniformly applied to all requests for that gateway" (the page describes no per-user keying).
9. [Documented] Caching is off by default. It covers text and image responses and "applies only to identical requests". The default cache key is a SHA-256 hash of provider + endpoint + model + provider auth header + full request body, so any change in messages, tools or parameters is a new entry. Cloudflare says it suits "use cases with limited prompt options"; semantic caching is only "planned". The cache is volatile: two identical simultaneous requests may both go to the provider.
10. [Documented] Cache headers: `cf-aig-cache-ttl` (minimum 60 seconds, maximum one month), `cf-aig-skip-cache`, `cf-aig-cache-key` (custom key; opts the request into caching; TTL is 5 minutes if no TTL header and no gateway default). The response header `cf-aig-cache-status` is HIT or MISS. Old names `cf-cache-ttl` and `cf-skip-cache` still work.
11. [Documented] Cost tracking is an estimate based on tokens sent and received, and is only available where responses return token data and the model name. Cloudflare says to use the provider's dashboard for accurate costs. Custom per-request costs can override public rates.
12. [Documented] Pricing: AI Gateway runs on all plans; the core features (dashboard analytics, caching, rate limiting) are free. Logs: accounts whose first gateway was created on or after September 24, 2026 use Workers Logs pricing and retention. Legacy Logs limits are 100,000 logs total on Workers Free and 10,000,000 logs per gateway on Workers Paid. DLP is free. Guardrails are billed as Workers AI inference (Llama Guard 3 8B). Unified Billing adds a 5% fee on purchased credits ($100 credit = $105 charge), with provider token rates passed through at no markup; credit card only.
13. [Inferred] For this app, gateway caching gives almost nothing for personalized recommendation prompts: each user's taste profile and the tool results make every request body unique. It is a different mechanism from Anthropic's own prompt caching (prefix caching on the provider side), which is the one that cuts cost for a large shared system prompt.
14. [Inferred] Gateway rate limiting is a global safety valve per gateway (a backstop against a runaway bill), not per-user abuse control. Per-user limits still need to live in the developer's own backend (Worker or Edge Function) keyed on a verified user ID.
15. [Inferred] The `cf-aig-authorization` token is itself a credential that can spend the stored Anthropic key. It must never ship in the mobile app; the app should call the developer's own backend, which then calls the gateway (ideally through a Worker binding, which needs no token).

## Limitations or bias
- These are the vendor's own docs and naturally present the product favorably. Cost figures are explicitly estimates.
- Example code on the caching page uses OpenAI models; how caching interacts with Anthropic streaming responses is not described on the pages read.
- The rate-limiting page gives no maximum values, no per-key or per-user options, and no note on cross-location accuracy.
- I did not open the linked pages on credential precedence, Unified Billing, dynamic routes (budget limits), custom costs, or Workers Logs pricing.
