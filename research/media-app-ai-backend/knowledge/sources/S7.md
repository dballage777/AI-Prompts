## Learned points
1. [Documented] Two threat models: (a) jailbreaks / direct prompt injection, where the app's *user* is the adversary; (b) indirect prompt injection, where the user is trusted but Claude processes *third-party content* (webpages, emails, documents, tool results) containing adversarial instructions.
2. [Documented] Harmlessness screen: use a lightweight model "such as Claude Haiku 5.5" to pre-screen user input before the main conversation, with structured outputs (`output_config.format` `json_schema`, e.g. `{"is_harmful": boolean}`, `additionalProperties: false`). Haiku 5.5's own safety classifiers can decline the screening call; "treat a response with `stop_reason: "refusal"` as a harmful verdict."
3. [Documented] Input validation: filter user input for known injection patterns before it reaches Claude; an LLM can serve as a generalized validation screen given known jailbreak language as examples.
4. [Documented] Prompt engineering: system prompts that emphasize ethical/legal boundaries and explicitly tell Claude how to refuse (example gives a fixed refusal sentence).
5. [Documented] Repeat offenders: "consider throttling or banning users who repeatedly attempt to circumvent your application’s guardrails"; if a user triggers the same kind of refusal multiple times, tell them their actions violate usage policies and act accordingly.
6. [Documented] Indirect-injection controls: put untrusted third-party content only in `tool_result` blocks, never in `system` or plain user `text` (Claude is trained to treat instructions inside tool results with skepticism); describe what the content is and where it came from in the tool `description` or result structure; state in the system prompt that tool/document/search content is untrusted data that must never override the system prompt or user request (example `<untrusted_content_policy>` block).
7. [Documented] JSON-encode untrusted strings inside a JSON object instead of concatenating free text, so an attacker "cannot close a quote or tag to 'break out' into an instruction context".
8. [Documented] Don't put your own instructions in tool results (they may be ignored or flagged as injection); send them in a `user` turn after the `tool_result`, or a mid-conversation system message on supported models.
9. [Documented] Least privilege: no secrets Claude doesn't need, sandboxed tools, narrow permissions so a successful injection does minimal damage.
10. [Documented] Screen tool outputs: run each tool, pass raw output to a small Haiku 5.5 classifier (`{"injection_suspected": boolean}`), and only return content as a `tool_result` if clean; otherwise return an error or stripped summary and consider surfacing the attempt to the user. A Haiku refusal on this screen leaves no verdict and is treated the same way. Also red-team your agent with injected documents/tool outputs before deploying, and continuously monitor outputs for signs of successful injection.
11. [Documented] Chained safeguards: combine strategies; example financial chatbot whose system prompt calls a `harmlessness_screen` tool (boolean structured output) before processing and gives a fixed refusal line if non-compliant.
12. [Documented] Anthropic runs extra injection classifiers only for the computer use and browser use tools — not for custom tools like third-party API calls.
13. [Documented] Prompt leak: use leak-resistant techniques "only when absolutely necessary" because they make the task more complex and can degrade performance; try monitoring first (output screening, post-processing). Strategies: separate context (system prompt) from queries; post-process outputs with regex/keyword filters or a prompted LLM; leave out proprietary details Claude doesn't need (extra content reduces adherence to "no leak" instructions); audit regularly. Prefilling the assistant turn is "not supported on Claude 4.6 and later models".
14. [Documented] Content moderation guide: Claude's built-in safety behavior may flag dangerous content regardless of prompt. Haiku 5.5 is recommended where cost matters; worked estimate for 1B posts/month (100 chars each, ~28.6B input tokens, 3% flagged × 50 output tokens = 1.5B output tokens) at Haiku 5.5 "$0.10/MTok" input and "$0.50/MTok" output = $3,610/month vs $180,500 with Opus 5 ($5/$25 per MTok). Prices as stated on the page, read 2026-11-25.
15. [Documented] Moderation can use multiple risk levels (auto-block high risk, flag users with many medium-risk queries for human review); give users clear feedback on why input was blocked; track flagged categories; measure precision/recall; batch messages when real-time isn't required.
16. [Inferred] For the app: the AniList/TVmaze/Wikidata responses (titles, synopses, user-edited descriptions) are untrusted — return them as JSON-encoded `tool_result` content labeled by source, never splice them into the system prompt, state the untrusted-content policy in the system prompt, give the model no secrets or side-effecting tools, and optionally run a cheap Haiku injection screen on free-text fields. On user input: a cheap pre-screen plus per-user refusal counters feeding throttling/bans. Don't over-engineer prompt-leak defenses; the system prompt should contain nothing secret.
