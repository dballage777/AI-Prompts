## Learned points
1. [Reported] The story, as quoted in the top comment from the original post: a Firebase browser API key without API restrictions was used for Gemini requests. "We had a budget alert (€80) and a cost anomaly alert, both of which triggered with a delay of a few hours"; "By the time we reacted, costs were already around €28,000"; "The final amount settled at €54,000+ due to delayed cost reporting." Timeline: 13 hours.
2. [Reported] Root cause most commenters identify: for years Google said Google API keys (Maps, Firebase) are "public by design", identifiers rather than secrets. Firebase docs say authorization is handled by IAM, Security Rules and App Check. But once the Gemini API is enabled on the project, the same unrestricted browser key can call Gemini. One commenter: "the key initially wasn't a secret but became a secret once we enabled Gemini API with no warnings". They reported $26k of damage caught early by alerting and a refund request that was initially denied and is now under reconsideration.
3. [Reported] A comment quotes the Gemini product lead's response: "We are moving to disable the usage of unrestricted API keys in the Gemini API". It links an earlier HN thread (item 47156925) about the same key-scope change.
4. [Reported] The most repeated lesson is that budget alerts are not caps. Alerts arrive hours late, and several commenters report 5–6 hour delays on GCP budget emails or notifications. One wired a budget notification to a kill switch, but the notification itself came 6 hours late. The GCP documentation quoted in-thread says the delay "may be hours or days"; another commenter: "I managed to spend $400 in 5 minutes."
5. [Reported] Gemini-specific caps (claims by commenters presenting as Google/Gemini staff, unverified): Gemini API now has monthly spend caps at billing-account tier and project level, with "up to a 10 minute delay"; "By default, new Tier 1 paid accounts can only spend $250 in a given month"; a Gemini prepay option (cited as new from March 23) under which "all API keys in all projects linked to that billing account will stop working" at $0 balance (quoted from ai.google.dev billing docs). Others note developer spend caps default to off.
6. [Reported] Workarounds repeated in the thread: lower per-API quotas yourself (described as near real time, unlike billing); a budget → Pub/Sub → Cloud Function that disables billing (Google's documented emergency stop, with a warning that it can destroy resources); restrict keys by API (e.g. `generativelanguage.googleapis.com` only) and by HTTP referrer; use prepaid or hard-capped providers or routers (OpenRouter, DeepSeek-style prepaid; Backblaze B2 caps cited as working).
7. [Reported] Several commenters push back that referrer/IP restrictions do not protect a key called from browser JavaScript: users' IPs are unknown, and Referer/Origin headers can be spoofed outside a browser. Client-side keys stay abusable.
8. [Reported] Why attackers want LLM keys (speculation in-thread): resale of discounted inference, spam and phishing generation, distillation data for competitors, and brute-force token-heavy tasks billed to someone else.
9. [Reported] Debate on whether real-time hard caps are possible: one side says billing is batch-aggregated, so exact caps are hard; the other says caps "within a dollar or five minutes" are feasible, and that telecom and prepaid services do it. One commenter claims Google AI Studio Build Mode recommends a publicly exposed proxy with no protection (link to a personal blog, not verified).
10. [Reported] A second anecdote quoted from the Google forum: a $6,909 bill over about a month for `GenerativeLanguage.GenerateContent` calls on a key created during a live training session, which the owner says was never shared.
11. [Inferred] For this app: never use a client-visible key of any kind (Firebase/Expo public config included) on a project that also has an LLM API enabled. Keep the Claude key server-only in its own project/workspace. Set a hard provider-side spend limit, not only alerts. Add your own server-side per-user and global daily token/cost ceilings that stop calls immediately, since provider billing signals can lag by hours.
12. [Inferred] Separate the cloud project that holds LLM access from any project whose keys ship in the app bundle, so enabling an AI API cannot silently turn a "public" key into a billing credential.
