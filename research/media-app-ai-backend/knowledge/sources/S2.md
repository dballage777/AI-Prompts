## Learned points
1. [Documented] Standard prices per MTok, USD (input / 5m cache write / 1h cache write / cache hit+refresh / output): Claude Opus 5.5 $4 / $5 / $8 / $0.20 / $20. Claude Sonnet 5.5 $2 / $2.50 / $4 / $0.10 / $10. Claude Haiku 5.5, prompts up to 100,000 tokens: $0.10 / $0.125 / $0.20 / $0.01 / $0.50; prompts over 100,000 tokens: $0.50 / $0.625 / $1 / $0.05 / $2.50.
2. [Documented] Cache-hit multipliers: 0.05x base input on Opus 5.5 and Sonnet 5.5; 0.1x on Haiku 5.5 and most other models; 0.025x on Fable 5.2/5.1 and Mythos 5.2/5.1. Write multipliers are 1.25x (5m) and 2x (1h) for every model. Caching pays off after 1 read (5m) or 2 reads (1h).
3. [Documented] Batch API: 50% off input and output. Batch per MTok (input / output): Opus 5.5 $2 / $10; Sonnet 5.5 $1 / $5; Haiku 5.5 $0.05 / $0.25 (≤100k-token prompts) and $0.25 / $1.25 (>100k). Batch discount stacks with caching. Results arrive within 24 hours (optimizing page). Fast mode is not available with Batch.
4. [Documented] Haiku 5.5 long-prompt tier: a request whose prompt is over 100,000 tokens pays the higher prices on ALL its tokens (output too — the optimizing page says "every token of the request costs 5 times as much, output included"); prompt length counts all input tokens including cache reads and writes; each request is priced on its own. The optimizing page advises compacting before 100k on Haiku 5.5 (and setting compaction `trigger` a bit below 100,000; default is 150,000).
5. [Documented] Other current models have the 1M context window at standard pricing (no long-context surcharge) — "Claude 4.6 and later models (except Claude Haiku 5.5)". All three 5.5 models: 1M context, 128K max output (300K on Batch with beta header `output-300k-2026-03-24`), text+image input → text output, knowledge cutoff Jun 2026.
6. [Documented] Tool use system prompt overhead (added whenever `tools` is provided): Opus 5.5 286 tokens, Sonnet 5.5 286 tokens, Haiku 5.5 286 tokens for `tool_choice` auto/none; for any/tool: Haiku 5.5 406 tokens, Opus 5.5 and Sonnet 5.5 blank in the table. Tool definitions (`tools` names/descriptions/schemas), `tool_use` blocks and `tool_result` blocks are billed as normal tokens.
7. [Documented] Web search: $10 per 1,000 searches plus token costs; search results count as input tokens in that turn and later turns; failed searches not billed. Web fetch: no extra charge beyond tokens (use `max_content_tokens`; ~2,500 tokens per average 10 kB page). Code execution is free when used with `web_search_20260209`/`web_fetch_20260209` or later; otherwise 1,550 free hours/org/month then $0.05 per container-hour (5-minute minimum).
8. [Documented] `inference_geo: "us"` applies a 1.1x multiplier to all token categories (input, output, cache writes, cache reads) on Claude 4.6+ models; default `"global"` is standard price. Models before 4.6 return 400 if the parameter is sent.
9. [Documented] Fast mode (`speed: "fast"`, up to 2.5x output tokens/sec): Opus 5.5 $8 input / $40 output per MTok (2x standard). Not available for Sonnet 5.5 or Haiku 5.5 per the list (available for Fable 5.2, Mythos 5.2, Opus 5.5, Opus 5, Opus 4.8). Switching speed mid-conversation misses the cache.
10. [Documented] Tokenizer: Claude 4.7 and later (including all 5.5 models) produce ~30% more tokens for the same text than earlier models; count tokens against the model you will use. Haiku 5.5 overview: ~30% more tokens than Haiku 4.5.
11. [Documented] Token counting endpoint `POST /v1/messages/count_tokens` is free, rate-limited separately from Messages (Start 5,000 RPM, Build 10,000, Scale 20,000). Returns an estimate; errors on server tools (web search/fetch, code execution, tool search), MCP connector, and url/file image/document sources. Does not use caching.
12. [Documented] Model choice: Haiku 5.5 is "Fastest" latency, default effort `medium`, built for "high-volume, latency-sensitive" classification, extraction, routing, subagent tasks; Sonnet 5.5 "Fast", default effort `high`; Opus 5.5 "Moderate", default effort `medium`, adaptive thinking always on. "Most workloads start with Claude Opus 5.5" (selection matrix), but "efficiency-first" start with Haiku 5.5 is recommended for prototyping, tight latency, cost-sensitive, high-volume tasks.
13. [Documented] Sampling params: on Haiku 5.5 "Omit `temperature`, `top_p`, and `top_k`"; on Sonnet 5.5 setting any of them returns a 400. Adaptive thinking is on by default on both; on Haiku 5.5 thinking counts toward `max_tokens`, so a small `max_tokens` can end a response before any text — raise it or lower effort. Sonnet 5.5 lowest thinking setting is `between_tools` (works at `high` effort or below).
14. [Documented] Cost levers from the optimizing page: turn on prompt caching first (agent loops read a median 84% of input from cache; below ~80% look for something breaking the cache); compare models on cost per completed task, not per token; tune effort before switching models; for checkable outputs, run at `low` and re-run failures at `high` (~40% cheaper than all-`high` at same pass rate); ask for shorter answers (output costs 5x input on the 5.5 models); defer unused tools via tool search; use a workspace spend limit as the backstop.
15. [Documented] Measured (Anthropic-internal, directional): Haiku 5.5 on GPQA Diamond 85% vs 91% for Opus 5.5/Sonnet 5.5 at about 1/20 of Opus 5.5's and 1/10 of Sonnet 5.5's cost per correct answer; Haiku 5.5 passed 93% of a Managed Agents task set at ~$0.011 per passed attempt.
16. [Documented] Cache-duration guidance: turns seconds apart → 5-minute default; ~1 gap in 20 between 5 min and 1 hour → 1-hour; on Haiku 5.5 use the generic ("Any") rows. Keep-alive: resend previous request with `max_tokens: 0` (no `stream`) within 4 minutes of the previous request's start. Choose the TTL at conversation start (switching later rewrites the whole prompt once).
17. [Documented] Putting a changing status line/timestamp at the front of the system prompt made every request a full cache write in Anthropic's test; move per-request text to the end of the newest user turn.
18. [Documented] New users receive free credits to test the API; billing is monthly usage, USD, credit card or invoicing.
19. [Inferred] Rough per-request cost for this app (Haiku 5.5, ≤100k prompt): 3,000 cached prefix tokens ($0.00003) + 1,000 uncached input ($0.0001) + 500 output ($0.00025) ≈ $0.00038; the same on Sonnet 5.5 ≈ $0.0003 + $0.002 + $0.005 ≈ $0.0073; Opus 5.5 ≈ double Sonnet 5.5 (~$0.015). Tool round-trips (verify each title via AniList/TVmaze/Wikidata) multiply request count, and each tool result re-enters as input on later turns. Real numbers must be measured from `usage`.
20. [Inferred] For a solo developer: start on Haiku 5.5 for brainstorming/verification steps, cap `max_tokens` with thinking in mind, keep requests under 100k tokens, and consider Sonnet 5.5 only for the "explain picks" step if quality evals require it.
