## Learned points
1. [Documented] Package `@anthropic-ai/sdk` (`npm install @anthropic-ai/sdk`); README describes it as for "server-side TypeScript or JavaScript applications". TypeScript >= 5.0. Client reads `process.env['ANTHROPIC_API_KEY']` by default.
2. [Documented] Supported runtimes: Node.js 20 LTS or later (non-EOL), Deno >= 1.28.0, Bun >= 1.0, Cloudflare Workers, Vercel Edge Runtime, Jest >= 28 with `"node"` environment (not `"jsdom"`), Nitro >= 2.6. Web browsers are "disabled by default to avoid exposing your secret API credentials"; enable only by setting `dangerouslyAllowBrowser: true`.
3. [Documented] "Note that React Native is not supported at this time."
4. [Documented] `dangerouslyAllowBrowser` "exposes your secret API credentials in the client-side code"; any user can "inspect, extract, and misuse" them. Docs list only internal tools with trusted users, or temporary dev/debug with short-lived, non-production, frequently rotated keys, as possibly acceptable. Zero-data-retention orgs cannot call the API from a browser at all (401).
5. [Documented] Streaming: `client.messages.create({..., stream: true})` returns an async iterable of raw events (less memory, no accumulation); cancel with `break` or `stream.controller.abort()`. `client.messages.stream({...})` returns a `MessageStream` with event handlers and accumulation.
6. [Documented] `MessageStream` events: `connect`, `streamEvent(event, snapshot)` (unknown event types passed through, snapshot unchanged), `text(textDelta, textSnapshot)`, `inputJson(partialJson, jsonSnapshot)`, `message` (= `message_stop`), `contentBlock` (= `content_block_stop`), `finalMessage`, `error(AnthropicError)`, `abort(APIUserAbortError)`, `end`. Methods: `.abort()` (also aborts in-flight requests), `await .done()`, `.currentMessage`, `await .finalMessage()` (throws if no message), `await .finalText()`; fields `.messages`, `.controller` (AbortController).
7. [Documented] Retries: by default up to 2 retries (3 attempts) on connection errors, timeouts, 408, 409, 429 and 5xx. An `x-should-retry` header (`true`/`false`) overrides the status; waits per `retry-after` header or short exponential backoff. Configure with `maxRetries` (client or per-request; default 2, 0 disables).
8. [Documented] Timeouts: default 10 minutes. For large `max_tokens` without streaming, the default is computed as `max(600 s, 3600 × maxTokens / 128000 s)`, up to 60 minutes. Configure with `timeout` (ms) at client or request level; on timeout `APIConnectionTimeoutError` is thrown, and timed-out requests are retried twice by default.
9. [Documented] Long requests: the SDK throws an error if a non-streaming request is expected to take longer than roughly 10 minutes; passing `stream: true` or overriding `timeout` disables that. Avoid large `max_tokens` without streaming because networks may drop idle connections. The SDK sets TCP keep-alive where `fetch` supports it.
10. [Documented] Error classes: a subclass of `Anthropic.APIError` is thrown for connection failures and 4xx/5xx responses; `err.status` and `err.headers` (e.g. `err.headers?.get("retry-after")`) are `undefined` with no response. `APIUserAbortError` (you aborted via `signal` or `stream.abort()`) is not an `APIError`. `AnthropicError` is the parent of `APIError` and covers SDK-side failures (e.g. refusing a long non-streaming request). Per-code classes exist, e.g. `Anthropic.EnforcedSpendLimitReachedError` (from handle-errors page, see S5).
11. [Documented] Request IDs: every object response has `_request_id`, taken from the `request-id` response header (e.g. `req_018EeWyXxfu5pfWkrYcMdjWG`), for logging failures and reporting to Anthropic.
12. [Documented] Versioning: SemVer, but some backward-incompatible changes (types-only, internals, rarely-hit) may ship in minor versions. Each SDK major version pins the API version current at its release; v1.0.0 is the first to use API version `2026-10-21`; move API versions by upgrading majors.
13. [Documented] Other helpers present: structured outputs (`zodOutputFormat`, `jsonSchemaOutputFormat`, Standard Schema), tool helpers (`betaZodTool`, `betaTool`, `client.messages.toolRunner`, `ToolError`), token counting, batches, logging and OpenTelemetry tracing, custom fetch and proxy configuration.
14. [Inferred] For the app: the SDK belongs in the backend (Node 20+, or Cloudflare Workers / Vercel Edge), never in the Expo/React Native bundle — RN is unsupported and `dangerouslyAllowBrowser` would leak the key. Set an explicit short `timeout` and conservative `maxRetries` on user-facing calls (default 10-minute timeout × 3 attempts is far too long for a phone UI), log `_request_id` with every failure, and pin the SDK major version since it determines the API version.
