## Learned points
1. Endpoint: GET https://data.usajobs.gov/api/Search. The tutorial writes it in lowercase as /api/search. All interactions are over HTTP(S) GET. — [Documented]
2. Every request needs three headers. Host is `data.usajobs.gov`. User-Agent is the email address used when requesting the key. Authorization-Key is the API key. — [Documented]
3. To get a key, fill out the form at /apirequest/. Required fields are first name, last name, email, contact phone, company or agency, and a description of intended use (255-character limit). You must also agree to the USAJOBS Terms of Service. The codelist APIs need no authentication. — [Documented]
4. Search parameters: Keyword (searches the full announcement, including synonyms) and PositionTitle (title contains the value). Location filters are LocationName plus Radius. RemoteIndicator=True returns remote jobs only, False excludes them, and remote jobs are included by default. Pay filters are RemunerationMinimumAmount/MaximumAmount and PayGradeLow/High (01–15). Other filters: JobCategoryCode (occupational series, e.g. 2210 = IT Management), Organization (agency subelement code), PositionScheduleTypeCode (1 full-time, 2 part-time, 3 shift, 4 intermittent, 5 job sharing, 6 multiple), PositionOfferingTypeCode, TravelPercentage, RelocationIndicator, SecurityClearanceRequired (0 none through 8 other), SupervisoryStatus, DatePosted (0–60 days), JobGradeCode, HiringPath (e.g. public, vet, disability, student, graduates), WhoMayApply, SalaryBucket/GradeBucket, MissionCriticalTags, Fields (Min or Full), SortField (e.g. opendate, closedate, jobtitle, salarymin, location), and SortDirection (Asc/Desc). — [Documented]
5. Some parameters take multiple values. The API reference says to separate them with semicolons, while the tutorial says colons. This is an inconsistency in the docs, so test before relying on it. — [Documented]
6. Paging: use Page with ResultsPerPage. The default is 25 per request and the maximum is 500. The response returns NumberOfPages. — [Documented]
7. Limits: at most 10,000 rows per query and 500 rows per page. Searches return only public jobs by default, and status jobs require an additional request. The Code List API and Dynamic Search have no limits. No per-second or per-day request quota and no HTTP error codes are stated. — [Documented]
8. WhoMayApply accepts All, Public, or Status. All and Status require specific authorization. The request form says "Only public job information is available through this site." — [Documented]
9. Response structure: SearchResult has SearchResultCount (returned), SearchResultCountAll (total matches), and SearchResultItems. Each MatchedObjectDescriptor includes PositionID, PositionTitle, PositionURI, ApplyURI, PositionLocation, OrganizationName, DepartmentName, JobCategory, JobGrade, PositionSchedule, QualificationSummary, PositionRemuneration, PublicationStartDate, and ApplicationCloseDate. UserArea.Details includes MajorDuties, Education, Requirements, KeyRequirements, HowToApply, RequiredDocuments, WhoMayApply, Benefits, JobSummary, and more. — [Documented]
10. ApplyURI carries a PostChannelID (default RESTAPI). Partners can request their own from recruiter-help@usajobs.gov. — [Documented]
11. Terms of use: public data may be copied, analyzed, published, and redistributed for lawful purposes without prior OPM approval. Attribution is encouraged: cite USAJOBS, link the official announcement, note the retrieval date, and state that the product is not endorsed by OPM. — [Documented]
12. Terms also say: you may not present modified data as official or imply OPM or federal endorsement. Applicants must follow the instructions in each announcement. Keep credentials confidential. Do not circumvent rate limits or authentication, access nonpublic data, or use the service for phishing, fraud, or deceptive collection of applicant data. — [Documented]
13. The service is provided "as is." OPM does not guarantee error-free results, users should verify announcements against official sources, and OPM does not archive public data. OPM may change rate limits or discontinue the service. — [Documented]
14. Data scope: public announcements and reference data only. No applicant profiles or account data. — [Documented]
15. Bot implication: a resume-matching bot can map resume skills to Keyword, PositionTitle, or JobCategoryCode, and location preferences to LocationName, Radius, or RemoteIndicator. It should show ApplicationCloseDate and send users to PositionURI or ApplyURI on usajobs.gov. It should never imply OPM endorsement, and it must keep the API key server-side and private. — [Inferred]

## Limitations / bias
- The docs are partly inconsistent: semicolon vs. colon separators, `UserAreas` vs. `UserArea`, and a confusing NumberOfPages definition in the tutorial.
- No numeric request-rate quota or error codes are given.
- I read content through WebFetch summaries, so parameter descriptions are paraphrased.
- The API covers federal jobs only, not private-sector or state jobs.
