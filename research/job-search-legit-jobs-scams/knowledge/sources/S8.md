## Learned points
1. Endpoint: GET /api/historicjoa on host data.usajobs.gov; returns "smaller fields for all current and past job postings to USAJOBS" as a bulk data set to be parsed by the consumer. — Documented
2. No key needed: the Historic JOA endpoint "does not require authorization or authentication"; data is "publicly consumable." — Documented
3. Contrast: the Authentication guide says other USAJOBS APIs (e.g., /api/search) require an API key requested via application, sent in three headers: Host (data.usajobs.gov), User-Agent (the email used to request the key), Authorization-Key (the key). Code-list APIs need no authentication. — Documented
4. Query parameters (any combination): HiringAgencyCodes, HiringDepartmentCodes, PositionSeries (occupational series), AnnouncementNumbers, USAJOBSControlNumbers, StartPositionOpenDate, EndPositionOpenDate, StartPositionCloseDate, EndPositionCloseDate; plus continuationtoken for paging. — Documented
5. Paging: response has paging.metadata (totalCount, pageSize, continuationToken) and paging.next URL; sample shows pageSize 1000; keep requesting until no continuation token is returned. — Documented
6. Status field: positionOpeningStatus = hiring status — accepting applications, reviewing applications, selected an individual, or canceled (sample: "Applications under review"). — Documented
7. Date fields: positionOpenDate, positionCloseDate, and positionExpireDate (actual close date if closed early); announcementClosingTypeDescription values: Closing Date, Open Continuous, Applicant Cut-Off, or Closing Time. — Documented
8. Other useful fields: positionTitle, hiringAgencyName/DepartmentName, announcementNumber, usajobsControlNumber, appointmentType, workSchedule, payScale, salaryType, minimumSalary/maximumSalary, minimum/maximumGrade, promotionPotential, whoMayApply, hiringPaths (e.g., "The public"), positionLocations (city/state/country), teleworkEligible, securityClearanceRequired, drugTestRequired, relocationExpensesReimbursed, jobCategories.series. — Documented
9. Data-type quirks: documentation lists some flags as boolean but sample returns "N" strings; sample shows salary 0.0 for an old record. — Documented
10. Live test (2026-11-15): keyless request with an agency + open-date filter returned JSON with 3 records; first record "Management and Program Analyst," status "Applications under review," open 2026-11-02, close 2026-11-06, salary 107446.0–139684.0, hiring paths internal/career transition. — Reported (via WebFetch summary; paging fields not shown in summary)
11. Rate-limit guide: Search Jobs API defaults to "Public" jobs only, max 10,000 rows per query, max 500 rows per page; Code List and Dynamic Search have no limits. No numeric limit stated for Historic JOA. — Documented
12. Bot implication: Historic JOA is a bulk/history dataset, not a live search; status and close dates must be checked (only show openings still accepting applications, and confirm against the live USAJOBS announcement); check hiringPaths/whoMayApply so a member of the public is not sent to internal-only jobs. — Inferred
13. Bot implication: for live keyword/location search matching a resume, the keyed Search API is the intended tool; Historic JOA suits keyless lookups by control number, agency, series, or date. — Inferred

## Limitations / bias
- No published date or version; no explicit rate limit for this endpoint.
- Text says pagination includes previous-page links, current page, and total pages, but sample shows only next link and totalCount/pageSize/token.
- Live call result came through a summarizing tool; only one small call made.
