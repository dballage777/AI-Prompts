## Learned points
1. O*NET Web Services is a REST API that serves the entire O*NET Database. It covers 900+ occupations, with about 500 standardized ratings per occupation, in an SOC-based taxonomy. The database is updated quarterly. — [Documented]
2. Access is free, but attribution is required. Parties must register via the Sign Up form, use the services only on registered sites or apps under their control, and give a URL and description of the app. The site reports 5,100+ registered users. — [Documented]
3. Authentication: every request needs an `X-API-Key` HTTP header. Keys are made and revoked in My Account, and several can be active per project. Keys are not accepted in the query string or in a POST body. All requests must use GET; POST is denied. — [Documented]
4. Base host is `https://api-v2.onetcenter.org`. Occupation keyword search is `GET /online/search?keyword=[phrase or code]`. It accepts a word, phrase, title, or full or partial O*NET-SOC code and returns occupation code, title, href, and an optional bright_outlook tag. — [Documented]
5. Keyword results are sorted closest match first (or by code for code searches) and come 20 per page by default. The ranking method is documented in "A Weighted O*NET Keyword Search (WWS)." My Next Move has a parallel endpoint, `/mnm/search?keyword=`, for a career-seeker audience. — [Documented]
6. Mapping a job title to skills is a two-step chain: keyword search gives an O*NET-SOC code (e.g., 17-2051.00), then `/online/occupations/{code}/summary/skills` gives the top skill descriptors (5 per page by default), with "related" links to other occupations where each skill is important. — [Documented]
7. Other endpoint families relevant to resume matching: Skills (Basic, Cross-Functional) browse, details/skills, details/technology, related occupations, Hot Technology browse, Soft-skills custom list, Job duties custom list, and crosswalks (Military/MOC, SOC, DOT, ESCO, CIP education, RAPIDS apprenticeship, OOH). Some of these paths were seen only in the navigation and were not opened. — [Documented]
8. Paging uses start (1-based) and end. The maximum page size is 2000. Responses include total, plus prev and next links. — [Documented]
9. Errors: 422 with a JSON error for missing or bad parameters, obsolete or non-existent SOC codes, or no data (e.g., no Knowledge data for Legislators). Clients should also handle 404 and 500. — [Documented]
10. Limits: service is "best-effort." Users who exceed 5 requests per second or 50,000 requests per day may be throttled or suspended. A 429 response means delay at least 200 ms before retrying. The overview says no hard maximum is currently imposed. Caching is advised because most data updates quarterly or annually. — [Documented]
11. Attribution (ToS term 5): a URL or link to O*NET Web Services must appear prominently near the information. The suggested credit text is in Key quotes. — [Documented]
12. Integrity rules: do not alter or modify the information, though reformatting is allowed if it does not change accuracy, attribution, or intent. Do not present O*NET data as proprietary or exclusive. No illegal, harmful, or offensive use. — [Documented]
13. Paid or registration-required device apps must get permission (onet@onetcenter.org) before including O*NET data, unless the same information is also freely available without registration. — [Documented]
14. The data license is non-transferable. Account holders cannot pass sharing rights to third parties (e.g., clients of a downstream API). The license expires if the account is suspended. External-source content in results is not covered by it. — [Documented]
15. CC BY 4.0 applies to the site pages ("…licensed under a Creative Commons Attribution 4.0 International License"). Reference Manual documentation is excluded from the data license. The downloadable O*NET 31.0 Database may be shared under a Creative Commons license via a separate database-license page, which was not opened. — [Documented]
16. Trademark: write "O*NET®" and use it as an adjective (e.g., "with O*NET data"), never as a noun, verb, possessive, or plural. — [Documented]
17. Terms changes: features and interfaces may change with 30 days' email notice, and access may be terminated with 30 days' notice. Violators can be cut off immediately. — [Documented]
18. For the bot: O*NET maps resume titles and skills to standardized occupations and codes. It contains no job postings, so codes should be passed to a postings source such as CareerOneStop Jobs V2 (S14), which accepts O*NET codes as keywords. — [Inferred]

## Limitations / bias
- Occupation-level data only, with no live job openings. Keyword matching is title or phrase based, so resume parsing must be done by the app.
- The Terms of Service date from 2019. The rate guidance is "guidance," not a hard cap.
- The database CC license page and the external data sources page were not opened.
## Best for
- Specifying how the bot maps a user's resume or job title to O*NET occupations and skills, with the exact auth, limits, and attribution rules it must follow.
